# Proteomics stages and pack-local records

Every checked-in input and output is a synthetic software fixture. This document defines procedure, not scientific evidence. No global schema, engine, receipt or MCP contract changes.

## Invocation and immutable identities

Run `python3 scripts/validate_proteomics_pack.py examples/workflow-proteomics-differential-abundance/pack.json`. The CLI has one positional `bundle` argument, no output option and no writes. Success prints `proteomics-result-v1` JSON on stdout, exit 0. A refusal prints JSON `{status: refused, finding: labelled-reason}` on stderr, exit 2, without a traceback. Argument errors use argparse exit 2. The public Python entry point is `codex_science.proteomics_pack.validate_proteomics_pack(path)`, returning the same result or a labelled ValueError. `specification_hash(value)` hashes sorted, compact UTF-8 JSON. `welch_test(first, second, minimum=2)` accepts finite log2 lists with genuine integer minimum; effects are second minus first. `benjamini_hochberg(values)` adjusts the complete supplied p-value list in input order. Welch reuses the existing standard-library Student-t helper with a common scale for numerical stability.

All references are `{path, sha256}`, with canonical POSIX paths relative to the bundle and lowercase SHA-256 of parsed bytes. Refuse absolute/drive paths, backslashes, `..`, redundant separators, dot components, controls and symlinked components. The selected entry pack accepts a nonempty str or Path of at most MAX_TEXT characters without controls, with no symlinked ancestor; wrong entry types receive input-path refusals. Each file uses lstat, O_NONBLOCK plus O_NOFOLLOW, fstat regular-file/size/identity checks and `read(MAX_BYTES + 1)`. FIFO, directory, device, symlink, swapped, growing and oversized inputs are refused. Parse each artifact once from a cached byte snapshot, hash those exact bytes, and separately reread/check hashes and file identities at the end. The bundle root and ancestors are opened as directories with O_DIRECTORY|O_NOFOLLOW; compare device/inode with lstat, resolved path and final reopening, refusing root swaps.

There is no writer or cross-file transaction. Two concurrent calls write nothing; a kill leaves no result file, partial record, lock or receipt. An input may still change after the final check returns. The coordinator writes outputs as immutable new artifacts and registers them using existing provenance tools; this pack never edits an existing ref or record. Hashes bind declared content, not historical freeze timing or genuine independence.

JSON must be a UTF-8 object, with no duplicate keys at any depth, NaN/Infinity, bool-as-number, huge numbers or malformed roots. Numeric magnitude is at most 1e100. Every declared integer (`seed`, `peptides`, `minimum_peptides`, `minimum_observed_per_group`) requires a real JSON int, excluding booleans, floats and strings. Negative and zero seeds are permitted. Wrong types and recursion are labelled refusals.

Named limits are enforced before work scales with each dimension: `MAX_BYTES = 67108864`, `MAX_DEPTH = 64` (root depth zero), `MAX_TEXT = 8192` characters including keys, `MAX_ITEMS = 20000` per generic JSON container, `MAX_SAMPLES = 256`, `MAX_PROTEINS = 10000`, `MAX_VALUES = 1000000` sample/protein cells, `MAX_CLAIMS = 1000`, `MAX_RECORDS = 1000` cached artifacts or references per list. The generic container bound is checked as JSON is admitted; domain bounds precede sets, cross products and per-protein work. These bound the reference route, not an existing stored record class. Equality at every limit is accepted when other controls hold. Empty protein/sample tables are invalid; an empty tested family is retained when all proteins fail controls. Empty claims and study-output lists are valid.

## Pack-local schemas

All input records require `fixture: true` and their named `schema`. Objects reject missing and unknown fields; these are new pack-local records registered only as ordinary artifacts. They are separate from existing claim-register entries. `IDENTITIES` means the nonempty strings `organism`, `database_name`, `database_version`.

| Schema | Required fields besides schema/fixture |
| --- | --- |
| `proteomics-pack-v1` | `stages` exactly as plan.json; `inputs` containing `design` and `intensities` identities; `frozen_spec`, `analysis_spec`, canonical `frozen_sha256`; `frozen_design_sha256` matching design identity; `freeze_before_intensities: true`; boolean `exploratory`; `study_outputs` identities; `claims`. |
| `proteomics-design-v1` | IDENTITIES and nonempty `samples`: each has unique `id`, unique `biological_unit`, `replicate_type: biological`, `condition`, `batch`, IDENTITIES equal to design. Duplicate biological units and technical runs are refused. |
| `proteomics-intensities-v1` | IDENTITIES equal to design, ordered `sample_ids` matching samples, integer `seed`, nonempty `proteins`: each has unique `id`, nonnegative integer `peptides`, boolean `decoy`/`contaminant`, aligned `values` (positive raw intensities or null), aligned boolean `imputed` flags. Supplied imputed values require both original and active rules to declare imputation; they never become observed. |
| `proteomics-evidence-v1` | Nonempty `kind`, `result`, `origin`, `protein_id`. Origin is study, external, independent or preregistered. Positive support requires `kind: statistical-evidence`, `result: protein-level-association` and matching protein ID. Approval or computation in either kind or result is refused for every positive status. These declarations alone cannot prove scientific support. |
| `proteomics-result-v1` | `stages`, `evidence_level: statistical-only`, `review: unavailable`, `exploratory`, `frozen_sha256`, active `specification_sha256`, all admitted `input_identities` (including entry pack and evidence), `qc`, `normalization_offsets`, `normalized`, `differential`, `claims`, `limitations`. |

Both specifications contain exactly: ordered two-string `contrast`, `replicate_unit: biological_sample`, `normalization` (`median-log2` or `none`), `missing_rule`, `alpha` in [0,1], integer `minimum_peptides` in [1,MAX_ITEMS], integer `minimum_observed_per_group` in [2,MAX_SAMPLES], `correction: BH`, `correction_scope: all-tested-proteins`, and `qc`. Missing rule is `{method: keep-missing}` or `{method: constant-log2, value: finite-log2-in-[-1000,1000]}`. QC contains `max_missing_rate` in [0,1] and `max_log2_total_deviation` in [0,1000]. None is a declared normalization alternative for sensitivity, never an implicit default. Changes preserve the original freeze and require exploratory status.

Claims contain exactly `id`, `kind`, `text`, `status`, `support` identities, `protein_id`. IDs are unique strings; kind is descriptive or associational. Existing status vocabulary is planned, supported, replicated, suggestive, conflicting, unsupported, withdrawn, unavailable. Empty support forces unavailable, including for a negative statement. Unavailable text cannot say supported, replicated, suggestive or significant. A positive claim requires the named protein's actual full-family BH hit. One synthetic study cannot establish replication; exploratory positives remain suggestive. Declared external/independent/preregistered evidence must differ by both path and hash from every study input and declared study output. Aliased copies remain dependent. Study outputs must themselves resolve as hashed JSON objects.

## 01-design: freeze

Inputs: `pack.json` and hashed `design.json`; freeze is checked before `intensities.json` is opened. Reuse `$cx-public-omics-dataset-discovery` and `$cx-mass-spectrometry-identification` context records for dataset fitness and upstream assay provenance; the reference invokes no external skill or executable. Output: admitted `proteomics-pack-v1` and `proteomics-design-v1` identities.

Fix contrast, independent biological units, batches, organism/database identities, normalization, missing rule, BH alpha and family, peptide/observed minima and sample QC before outcomes. A batch with no shared level between conditions is perfectly confounded and refused. Independent unpaired biological units nested in condition are allowed. Technical runs cannot increase n. Freeze records cannot independently attest their historical ordering. Failure: labelled design-freeze, technical-replicates, insufficient-replicates or batch-confounding refusal. Preserve failures in the coordinator record. Gate only for an essential unavailable input or interpretation-changing choice.

## 02-qc: identity and controls

Inputs: unchanged pack/design identities and `proteomics-intensities-v1` identity. Output: result `qc`, with per-sample `sample_id`, `total_intensity`, `missing_rate`, `log2_total_deviation`, `failures`. Totals and missing rates use genuinely observed non-decoy/non-contaminant protein rows, including low-peptide rows. The denominator is all such rows, with missing/imputed values counted as missing. Sum totals with math.fsum. A sample with no observed eligible intensities is refused; never turn it into a negative observation.

Compare absolute log2 total deviation from the median of sample log2 totals and missing rate to their frozen inclusive limits. A value equal to its limit passes; exceeding it retains a named failure. Failed QC marks every protein untestable; no positive hit is admitted. Preserve decoy and contaminant flags, peptide counts, measurements and null rows. Mixed sample database versions are refused. No outlier removal or automatic threshold change. No ordinary local gate.

## 03-normalization: observed values and missingness

Inputs: the same immutable identities and frozen specification. Output: `normalization_offsets` and `normalized`: each protein has `protein_id`, aligned `log2_intensities`, `observed` and `imputed` booleans. For each sample, take the median log2 genuinely observed eligible intensities; subtract its difference from the median of those sample medians. The none route has zero offsets. This assumes most proteins do not shift and warrants real-study sensitivity review.

Null remains null under keep-missing. A frozen constant-log2 rule fills only displayed missing slots after normalization. Supplied preimputed entries remain unobserved and are replaced by the declared display constant. All imputations are flagged and excluded from normalization, sample observed totals, observed denominators and Welch. Zero raw intensity is refused as zero-abundance. An imputation introduced after a keep-missing freeze is refused even with an exploratory label. No inference about absent protein follows from missing intensity. No ordinary local gate.

## 04-testing: Welch and BH

Inputs: unchanged identities and observed normalized log2 values. Output: every `differential` row includes `protein_id`, `peptides`, `decoy`, `contaminant`, two `observed` counts, `status`, `reasons`, `log2_fold_change`, `t`, `df`, `p_value`, `q_value`, `significant`. Reasons preserve decoy-or-contaminant, minimum-peptides, minimum-observed, zero-variance and sample-qc failures. Untestable rows have null numerical tests and null significance, distinct from tested nonsignificant rows.

For admitted proteins, use unpaired two-sided Welch: difference of mean normalized log2 values (second minus first), sample variances, Welch-Satterthwaite df and Student-t tail. Require both groups' observed minimum and positive variance; the numerical entry point refuses empty/nonfinite/degenerate data. Cache sample totals and group indices outside per-protein loops. BH includes all tested proteins after only the frozen pre-test controls. P-value/effect-selected families and raw-p-only decisions are refused. No batch adjustment or paired model is supplied; partial imbalance needs separate method review. No ordinary local gate.

## 05-handoff: bounded claims and independent review

Inputs: unchanged identities, full result, failures/nulls, assumptions, uncertainties, dependencies/conflicts and separate existing claim-register entries. Output: ordinary `proteomics-result-v1` artifact through `$science-provenance` and a coordinator-owned `$science-review` packet. The coordinator chooses rigor and registers review receipts. This pack leaves review unavailable and cannot approve its own result. The next measurement must discriminate a remaining interpretation, rather than merely add another report.

The conservative, case-insensitive English lexical gate uses whole-word prefix families with `\w*`: `caus`, `mechanis`, `therap`, `clinic`, `efficac`, `effective`, `treat`, `cure`, `prevent`, `recommend`, `prescri`, `bind`, `affinit`, `inhibit`, `activat`, `regulat`, `driv` (including drive/drives), `induc`. It additionally refuses the whole word truth and physical validity with spaces or hyphens. It applies to every claim status, even negations. This wording list is incomplete: independent review must assess unlisted paraphrases. Every positive status (supported, replicated, suggestive) checks both cited record kind and result for review/approval/computed/numerical/physical/clinical/truth labels and requires actual statistical association evidence. A claim kind label never bypasses it.

Association is never causality; computed agreement is never physical or clinical validity; absent records are unavailable, never negative evidence; review approval is never truth. Preserve failed controls and negative results. Use one checkpoint with the five ordered stage IDs in plan.json. Human gates occur only before installation, restricted transfers, new hosts, GPU/remote/heavy compute, or interpretation-changing choices. Offline fixtures authorize none of those external actions.
