# Microbiome composition stages and record contracts

All examples here are synthetic fixtures. The reference establishes statistical composition evidence only. Counts are relative information; composition differences have no causal, physical, therapeutic or clinical validity by themselves.

## Invocation and immutable identities

`python scripts/validate_microbiome_composition_pack.py BUNDLE` accepts one pack JSON file, prints one JSON object and writes nothing. Success exits 0 with `status=accepted`; a labelled refusal exits 2 with `status=refused` and `error="code: reason"`. `--help` exits 0. There is no output-file option, network, installer or execution engine. Public functions live in `src/codex_science/microbiome_composition_pack.py`: `validate_microbiome_composition_pack`, `reference_computation`, `clr_transform`, `alpha_diversity`, `welch_test`, `benjamini_hochberg`.

Every identity is exactly `{path, sha256}`, using canonical bundle-relative POSIX paths and lowercase SHA-256 of the bytes parsed. Absolute paths, parent traversal, backslashes, duplicate separators, symlinked components and escapes are refused. Open every absolute ancestor using pinned directory descriptors with O_DIRECTORY and O_NOFOLLOW. Compare lstat/fstat identities; open artifacts relative to the root using O_NONBLOCK and O_NOFOLLOW. Require regular files, bounded reads and stable metadata. Cache bytes and parsed objects by device/inode, including hardlink aliases. Recheck root ancestors and artifact hashes at the end. Transient ancestor/root swaps, growing inputs, FIFO/device/directory/symlink inputs, unavailable files and mismatching hashes are labelled refusals.

Concurrent calls only read the bundle and each prints its own JSON; they create no lock, ref, record or partial output file. A kill at any point leaves input files unchanged and may truncate that caller's stdout. Multi-file fixture creation is not transactional: a kill between writes leaves an incomplete or hash-mismatched bundle, which is refused. Freeze and register a complete bundle before consuming it. Read-once means one initial byte snapshot and parse per inode, followed by a final hash reread; no parser reread or hidden input substitution is allowed.

## Bounds fixed before computation

Module constants: MAX_BYTES=64 MiB per artifact; MAX_TOTAL_BYTES=256 MiB across distinct inodes; MAX_TOTAL_NODES=4,000,000 conservative JSON values across distinct parsed artifacts; MAX_RECORDS=128 artifact paths and support identities; MAX_ITEMS=20,000 items per JSON container; MAX_DEPTH=32; MAX_TEXT=4,096 characters per string/key; MAX_NUMBER=10^12 in absolute value; MAX_SAMPLES=64; MAX_TAXA=256; MAX_CELLS=16,384 sample-by-taxon cells; MAX_PERMUTATIONS=999; MAX_PERMUTATION_WORK=2,000,000 (permutations × retained sample count squared); MAX_CLAIMS=128; MAX_COUNT=1,000,000,000 per taxon count.

Check each dimension immediately after list admission and before sets, allocations, cross products or loops. The raw-byte allowance is checked against fstat size before each new read. Before JSON allocation, charge `1 + commas + nonempty-container-openers` using a non-consuming lookahead. This deliberately overcounts punctuation in strings. Refuse duplicate JSON keys at any depth, NaN/Infinity, non-object roots, huge numbers, malformed UTF-8, excessive nesting and invalid types. All declared integers (including every schema_version, count, depth, seed and permutation count) must be real int, never bool, float or numeric string. The declared integer bounds are inclusive. List/text limits accept equality, and invalid empty lists are refused; claims, study_outputs, support for unavailable claims and a standalone BH family may be empty.

## Pack-local schemas

All persisted domain records have `schema` as named below, `schema_version=1` as a real integer and `fixture="synthetic fixture"`. Unknown or missing fields are refused. Local records are ordinary registered artifacts, with separate claim-register entries; they never extend the existing global schemas.

- `microbiome-pack-v1`: headers plus `stages`, `design`, `table`, `report`, `applied_specification`, `exploratory` (boolean), `claims`, `study_outputs` (identity list). Stages are exactly 01-design, 02-qc, 03-composition, 04-taxa, 05-handoff. Design, table and report are identities. Claims have exactly `id`, `kind`, `text`, `status`, `taxon_id`, `support` (identities). IDs are unique strings; taxon_id is a taxon identity or `community`.
- `microbiome-design-v1`: headers plus `frozen_before_counts` (true boolean), `specification`. Read and hash this artifact before opening the count table. This is a checked declaration and ordering constraint, not independent proof of historical freezing.
- Specification fields: `contrast` (two distinct condition strings), `biological_unit="subject"`, `covariates=["batch","extraction_batch","sequencing_run"]`, `minimum_read_depth` (integer 1..MAX_COUNT), `prevalence_filter` (0..1), `zero_rule="add-pseudocount"`, `pseudocount` (10^-9..10^6), `diversity_indices=["shannon","simpson"]`, `distance="aitchison"`, `permutations` (integer 1..MAX_PERMUTATIONS), `seed` (integer 0..2^32-1), `permutation_strata` (all three covariates, unique), `fdr_alpha` (10^-9..0.5), `minimum_group_size` (integer 2..MAX_SAMPLES). Applied specification has the same fields; only labelled pseudocount/prevalence sensitivity may differ from the frozen record. Unsupported distances remain refused even when labelled.
- `microbiome-count-table-v1`: headers plus `taxa` (unique strings), `samples`. Every sample has `sample_id`, `biological_id`, `condition`, `batch`, `extraction_batch`, `sequencing_run`, `control`, `counts`. Control is `biological` or `negative-extraction-blank`. Counts are nonnegative integers in taxon order. Sample IDs are unique; biological IDs for biological rows are unique even when a row would be excluded for depth. Blank condition labels have no inferential role. Controls are retained in QC and never treated as independent biological samples.
- `microbiome-report-v1`: headers plus `design_sha256`, `exploratory`, `interpretation="statistical composition evidence only"`, `computation`. Recompute and compare the complete computation, preserving exact types for integer, boolean, null and string outputs, with numerical tolerance 10^-9 relative / 10^-12 absolute for floats.
- Computation has `qc` (sample_id, depth, retained boolean, reason), `sample_ids`, `filtered_taxa`, `control_taxa`, `low_depth_samples`, `clr` (rows in sample_ids order), `alpha_diversity` (sample_id, shannon, simpson), `aitchison_distance` (square matrix), `permanova` (pseudo_f, p_value, permutations, successful_permutations, seed, strata), `per_taxon`, `correction="benjamini-hochberg"`, `fdr_alpha`. QC reasons are retained, low-depth or negative-control. Each per_taxon row has taxon_id, prevalence, status, clr_difference, t, df, p_value, q_value, significant. Untested rows have null numerical test quantities and significant=false; statuses are tested, untested-control or untested-prevalence.
- `microbiome-evidence-v1`: headers plus `kind`, `result`, `origin`, `taxon_id`. Positive support requires kind statistical-composition-evidence and result taxon-association or community-association matching the claim and computed threshold. Origin is study, external, independent or preregistered. Both kind and result are inspected for review/computed/unavailable content. A label cannot prove independence.
- `microbiome-result-v1`: printed success record with headers, `status`, `interpretation`, `review="unavailable"`, `exploratory`, `stages`, `inputs` (all consumed identities), `computation`. Acceptance never means scientific review or biological validity.
- `microbiome-negative-cases-v1`: synthetic fixture headers plus `cases`; each has id, expected code and edits. Each edit specifies file and JSON-pointer-like path, and either value or delete=true. The focused tests materialize each negative example from the positive fixture, refresh hashes and exercise both public API and CLI. This test-only fixture collection is not an accepted study record.

## 01-design: freeze choices

Accepted identity: the complete design path and hash, before counts are read. Use `$cx-statistical-decision-analysis` to frame thresholds; use `references/plan.json` for the existing manifest `id/description/status` step shape. Output: `microbiome-design-v1` plus the existing coordinator checkpoint. Freeze the contrast, unit, all nuisance variables, depth, prevalence, zero rule, pseudocount, indices, distance, permutation count/seed/strata, minimum n and FDR threshold before outcomes. Unlabelled changes yield post-hoc-design; missing freeze declaration yields design-freeze. Preserve originals and failed revisions. Only a material interpretation-changing choice needs a human decision here.

## 02-qc: identity, depth and failed controls

Accepted identities: frozen design and count table paths/hashes. Call reference_computation through the validator. Output: report QC section (`microbiome-report-v1`) listing every row, depth, exclusion and blank. Biological depth equal to the minimum is retained; below it is listed and excluded. Keep blanks visible regardless of depth and flag all taxa with any positive blank count as untested-control. This conservative rule does not estimate contamination prevalence, detect every contaminant or infer a true biological absence. Prevalence is calculated over retained independent biological samples, inclusive at the frozen threshold.

Refuse duplicate-identity, technical-replicates, missing-controls, insufficient-units and confounded-design. For each nuisance variable, if every level has only one condition then it is perfectly confounded and refused. This check does not establish absence of partial confounding or adjust for covariates. Preserve failed controls; do not weaken the threshold. No routine human gate.

## 03-composition: CLR, diversity and permutation evidence

Accepted identities: frozen design, table and QC derivation. Output: CLR, alpha_diversity, aitchison_distance and permanova sections of `microbiome-report-v1`. Call clr_transform, alpha_diversity and reference_computation. After control/prevalence exclusions, add the same frozen pseudocount to each retained count, take natural logarithms, subtract their mean. Shannon is minus sum(p log p); Simpson is 1-sum(p squared) using unmodified relative counts on that identical filtered table. This distinguishes diversity probabilities from pseudocount CLR values.

Aitchison distance is Euclidean distance between CLR vectors. For N samples and two groups, total SS is sum of squared pair distances / N; within SS is the sum over groups of their squared pair distances / group size. Pseudo-F=(total SS-within SS)/(within SS/(N-2)). Exchange labels within joint frozen batch/extraction/run strata using random.Random(seed). Monte Carlo p=(1+number of permuted F at least observed)/(1+B), including ties and the observed pseudo-count. Preserve the declared B and seed. A draw with degenerate within-group variance counts as an unsuccessful draw, rather than being replaced or silently dropped; require 100% successful frozen draws or refuse permutation-degenerate. Other exceptions propagate as labelled errors. No inference from fewer draws.

Refuse fewer than two retained taxa, empty filtered sample totals, zero within-group distances, insufficient subjects, no exchangeable joint strata, permutation budget overruns, altered seed/count/strata or low-depth-retained. Never switch distance after outcomes to obtain significance. No routine human gate.

## 04-taxa: Welch and Benjamini-Hochberg

Accepted identities: frozen design and the same filtered CLR table. Output: every original taxon in `per_taxon`, with tested or explicit untested status. Call welch_test and benjamini_hochberg, reusing the existing stdlib Student-t implementation. Welch compares second minus first in natural-log CLR units, reports two-sided p and Satterthwaite df, and refuses either zero-variance group or n below the minimum. BH adjusts every tested p in one family; q equal to alpha counts as significant. Untested taxa have no p/q. Refuse fdr-required, degenerate-variance or output-mismatch instead of returning a significant-looking fallback. Retain nulls and negative results. Significance is not effect importance. No routine human gate.

## 05-handoff: bounded claims and independent review

Accepted identities: design, table, complete report, evidence sources, reference-use ledger and separate existing claim register; hash all handoffs through `$science-provenance`. Output: `microbiome-result-v1` plus the coordinator-owned review packet for `$science-review`, never a self-issued receipt. Review modes are record, source and method. Record conflicts, failed controls, nulls, assumptions, source dependencies, inclusion/exclusion rationale, applicability, uncertainty and the smallest falsifiable next action. The coordinator owns rigor classification, one checkpoint per run, ordinary domain artifact registration and separate claim entries.

All statuses are validated as strings before membership checks: planned, supported, replicated, suggestive, conflicting, unsupported, withdrawn, unavailable. Empty support requires unavailable status. ANY cited kind or result unavailable requires unavailable status, including mixed citations and negative claims. Unavailable text cannot say supported, replicated, suggestive or significant. Replicated is always refused for this one-study reference. Positive claims require the frozen permutation threshold for community or full-family BH threshold for a tested taxon; negative-control taxa can never be findings. Exploratory changes permit suggestive claims only.

Check both record kind and result for review approval and computed/numerical agreement; neither supports positive claims. External/independent/preregistered records may not share any study input/output path or hash, including hardlink/copy aliases. These checks bound local lineage, never prove historical preregistration or actual independence.

Conservative English whole-word prefix families (case insensitive): caus*, mechanis*, therap*, clinic*, efficac*, effective*, treat*, cure*, prevent*, recommend*, prescri*, bind*, affinit*, inhibit*, activat*, regulat*, drive/drives/driv*, induc*. Additional blocked terms are truth, physical validity, patient benefit, biomarker and dysbiosis. All claim text, regardless of kind/status, is checked. Separate gates conservatively refuse absolute wording and microbial/taxon/total load, and absent/absence/eradicated wording. The lexical gate includes negations and is incomplete for unlisted paraphrases or other languages; independent review remains essential. Boundaries run before later report reconciliation so a boundary refusal is not masked by a later output check.

Human gates apply only before installation, restricted transfers, new hosts, GPU/remote/heavy compute or interpretation-changing choices. This reference performs none of the external operations. Missing records are unavailable, never negative evidence; review approval is never truth; failed controls and negative results remain preserved.
