# Growth curve stages and local records

All examples, data, expected numbers and negative cases are synthetic fixtures. They check offline arithmetic only. They establish neither measured biological outcomes nor scientific validity.

## Invocation

Public entry points are `codex_science.growth_curve_pack.validate_growth_curve_pack(bundle)` for immutable files and `compute_growth_curve(data, protocol)` for in-memory synthetic records. The validator compares a supplied report against the calculation, validates evidence boundaries, then rechecks all inputs. Both return Python objects; the CLI serializes one JSON object.

```bash
python3 scripts/validate_growth_curve_pack.py examples/workflow-growth-curve/pack.json
```

Exactly one bundle argument is accepted. Success prints JSON on stdout and exits 0. Every refusal, including missing, extra or unknown arguments, prints JSON with `status` equal to `refused` and a labelled `finding` on stderr and exits 2. Help stays plain usage on stdout and exits 0. There is no output-path option. No files are written. A second concurrent call leaves all inputs unchanged; interruption leaves no partial records, refs or files, although stdout can be incomplete. The coordinator captures durable output atomically and preserves failed controls and refusals as ordinary artifacts.

## Limits and immutable input admission

Artifact identities are exactly `{path, sha256}`. Paths are canonical relative POSIX paths under the bundle directory. Hashes are required lowercase 64-hex SHA-256 values. Refuse absolute paths, traversal, backslashes, symlinked components, non-regular files and aliases escaping the bundle. Labels such as independent never substitute for checking the actual bytes.

Pin every directory from the filesystem root to the bundle using descriptor-relative `O_DIRECTORY|O_NOFOLLOW` opens, lstat/fstat identity comparisons and a saved device/inode chain. Read artifacts relative to the pinned root: lstat regular-file check, `O_NONBLOCK|O_NOFOLLOW`, fstat regular-file/identity/size check, bounded read and post-read identity check. Parse and hash the same bytes. Cache raw bytes and parsed records by device/inode so hardlink aliases are read and parsed once. Final recheck verifies the entire ancestor chain, each admitted path and hash, and the ancestor chain again. Final reads each distinct inode once. Root or ancestor replacement, including replacement that preserves the bundle inode, is refused.

Module limits: `MAX_BYTES` 67108864 per artifact; `MAX_TOTAL_BYTES` 268435456 across distinct artifact inodes; `MAX_JSON_VALUES` 4000000 bundle-wide preparse value allowance; `MAX_WELLS` 384 per well, design and group collection; `MAX_POINTS` 4096 per time/OD vector and window; `MAX_RECORDS` 128 artifact paths, claims, total evidence records and citations per claim; `MAX_ITEMS` 8192 entries per generic JSON container; `MAX_STRING` 4096 characters; `MAX_DEPTH` 32; `MAX_NUMBER` 1e100 generic magnitude. Time is finite in [0,1e9], raw OD in [0,100], linear upper in [1e-12,100], blank stability in [0,100] and relative tie tolerance in [1e-15,1e-3].

All dimensions are checked before dimension-dependent work, including sets and per-window loops. `MAX_WINDOW_WORK` 2000000 additionally bounds assignments times available windows times window length, before any per-window calculation; equality passes. This aggregate bound prevents individually valid dimensions multiplying into expensive CPU work. The aggregate byte budget is checked against fstat size before reading a new inode; equality passes. Before JSON allocation, charge an upper bound of one plus comma count plus nonempty container count, using a streaming regular-expression iterator with non-consuming lookahead. The allowance is shared across distinct parsed inodes. No match list is allocated. Strict JSON refuses nested duplicate keys, NaN/Infinity, huge numbers, non-object roots, invalid UTF-8, excessive nesting and strings. All integer fields are real ints, never bool, float or numeric string. Wrong types receive labelled ValueError findings before membership or key operations.

## Pack-local schemas

These six schemas are ordinary domain artifacts, never extensions to global manifests, receipts or claim-register records. Every input record has exactly `schema`, `fixture` equal to `synthetic fixture`, and its listed fields; unexpected or missing fields refuse. There is no schema-version integer inside these records: the schema name carries the version. Quality metadata and benchmark metadata use real integer schema_version 1 under their existing contracts.

- `growth-pack-v1`: `protocol`, `data`, `report` identities; `evidence` list of evidence-document identities, possibly empty; `frozen_protocol_sha256` equal to protocol hash; boolean `frozen_before_od_read` true. Freeze is checked before OD admission. The bundle root is the pack's parent directory.
- `growth-protocol-v1`: nonempty unique `strains`, `conditions`, `blank_wells`; nonempty `assignments` of exactly `{well,strain,condition,biological_unit,replicate_type}`; `background`, `blank_stability`, `linear_range_upper`, `model`, `fit_method`, `start_values`, `tolerance`, `window_rule`, `window_points`, `minimum_points`, `maximum_contamination_flags`, `time_grid`, `time_unit`, `minimum_wells`. Assignment wells and blank wells are distinct. Strain/condition must belong to the frozen lists. Replicate type is technical or biological. Biological-unit identity is explicit even for technical wells. Background is subtract-pointwise-blank-mean or none. Model is model-free-maximum-slope; fit method is closed-form-ols; start_values is an empty list because this method has no iteration. Window rule is largest-log-od-slope-first-tie. Integer window_points is 2..MAX_POINTS; minimum_points is window_points..MAX_POINTS; maximum_contamination_flags is 0..MAX_WELLS; minimum_wells is 2..MAX_WELLS. Time grid is equal-no-interpolation and time_unit is nonempty text. Other models, methods, start values and grids refuse.
- `growth-data-v1`: `time_unit`, `background_applied`, `wells`. Unit and background declaration must match protocol. Each well is exactly `{well,times,od,contamination,edge,evaporation,fit_converged}`. The four flags are real booleans. Times and OD are nonempty numeric lists of equal length. Times strictly increase and equal every other well's grid. The well set equals exactly the protocol assignments plus blanks. Data always contains raw OD: background_applied declares the subtraction performed by this calculator, never authorizes already-subtracted data. Blank mean is computed once per timepoint. Each blank's max-minus-min must not exceed blank_stability and blanks must have no sample QC flags. Count contaminated wells against the frozen maximum. A declared upstream failed fit is retained conservatively through fit_converged false; this model-free reference has no iterative fit whose success could override it.
- `growth-report-v1`: `protocol_sha256`, boolean `exploratory`, integer `window_points`, `computation`, `headline`, `claims`. Protocol hash must match. A changed window length requires exploratory true; the calculation is recomputed at that length and minimum_points is raised to at least the new length. Other method rules remain frozen. Headline and claims pass the wording gate before report-number checks. Computation must match the exact return shape below, with numerical relative tolerance 1e-9 and no absolute tolerance. Integer n, n_biological_units and window indices remain real ints even when the numerical value is unchanged.
- `growth-evidence-v1`: `records`, possibly empty, each exactly `{id,kind,result,origin,source}`. IDs are unique and strings; kind/result/origin are bounded nonempty strings; source is a required identity. Origin is internal, external, independent or preregistered. Every source is read and hash-checked. Non-internal sources cannot equal any study artifact path or hash, including renamed copies. Such labels cannot prove actual independence.
- `growth-result-v1`: `schema`, `fixture`, status offline-arithmetic-only, review unavailable, ordered `stages`, boolean `exploratory`, `inputs` listing every admitted path/hash, `computation`, checked `claims` and `limitations`. The pack never marks review passed. Synthetic numerical acceptance cannot establish historical freezing, actual biological independence or experimental validity.

Computation is exactly `{wells,groups,carrying_capacity_definition}` with carrying_capacity_definition observed-maximum-proxy. Each well contains the five assignment fields, `window_indices` and `parameters`. The five parameter keys are maximum_specific_growth_rate, lag_time, carrying_capacity, area_under_curve and doubling_time. Each parameter is exactly `{value,status,reason}`. Status is reliable with a finite numeric value and reason none, or unreliable with value unavailable and a retained reason. Group rows are exactly `{strain,condition,parameters}`. Each parameter summary is exactly `{n,well_ids,n_biological_units,replicate_unit,mean,standard_error,status,reason}`. Replicate unit is always well. Status is descriptive or unavailable. A well can never increase biological-unit count beyond its declared culture identity.

Claim proposals in the report are pack-local, exactly `{id,kind,status,text,evidence}`, and do not replace existing claim-register entries. Kind is descriptive or associational. Status is planned, supported, replicated, suggestive, conflicting, unsupported, withdrawn or unavailable. Evidence is a possibly empty list of unique admitted evidence IDs. Empty evidence requires unavailable. Any unavailable kind or result in any cited record requires unavailable regardless of other citations and regardless of whether the proposed status is positive or negative. Unavailable text cannot assert supported, replicated, suggestive or significan* evidence. Synthetic fixtures cannot establish replicated status, which is refused. Every positive status refuses any cited kind or result containing review, approv, comput, numer, agreement, truth, physical or clinic. Checking both fields prevents relabelled computed records or approvals becoming positive evidence. Evidence-boundary refusals precede report arithmetic discrepancies.

The conservative English wording gate uses these case-insensitive whole-word prefix families: caus*, mechanis*, therap*, clinic*, efficac*, effective*, treat*, cure*, prevent*, recommend*, prescri*, bind*, affinit*, inhibit*, activat*, regulat*, drive/drives/driv*, induc*. It also refuses fitness, resistan*, drug effect*, truth, physical validity and patient benefit. A star means word-character suffixes. This gate includes negations and is incomplete for unlisted paraphrases; independent source and method review remain necessary. It applies to all claim texts and headlines regardless of kind or status. Association is never causality, computed agreement is never physical or clinical validity, absent records are unavailable rather than negative evidence, and review approval is never truth.

## 01-rule-freeze

Calls: `$cx-statistical-decision-analysis` for framing, `validate_growth_curve_pack` for admission and `$science-provenance` for ordinary artifacts. Output: growth-protocol-v1 and its frozen identity in growth-pack-v1. Controls: every protocol field, including strain/condition/replicate/blank identities and all numerical thresholds, fixed before OD is read. Failure: protocol-freeze, unsupported-method, invalid-record or input findings; preserve refusal and stop. Hashes attest bytes, never historical preregistration. Human gates only for interpretation-changing choices or the external actions listed below.

## 02-data-qc

Accepted identities: unchanged protocol plus data path/hash. Calls: `compute_growth_curve` via the validator. Output: preserved growth-data-v1 and QC reasons in growth-result-v1. Controls: unique exact well identities; equal strictly increasing grids; finite OD; blank stability; declared edge, evaporation and contamination; frozen maximum flag count; subtraction checked and applied internally. Failure: well-identity, time-grid, blank-subtraction, unstable-blank, contamination-limit or input findings. No silent interpolation, clipping, deduplication or skipped blank. No further human gate for admitted offline fixtures.

## 03-per-well

Accepted identities: unchanged protocol/data plus report path/hash. Calls: local `compute_growth_curve` and `scripts/validate_growth_curve_pack.py`. Output: per-well parameters in growth-result-v1 checked against growth-report-v1. Controls: if any raw OD exceeds the linear upper bound, the well is saturated; equality passes. Saturation, fewer points than minimum, upstream non-convergence or declared sample QC flags make all five parameters unreliable and excluded. Preserve each reason. Valid wells must have strictly positive corrected OD before taking logs; zero and negative values refuse as nonpositive-log-od. No missing result is replaced with zero.

For each consecutive frozen-length window compute centered OLS slope of log OD against time. Choose the largest slope, retaining the first window among relative ties using only protocol tolerance, never an absolute tolerance. The maximum specific growth rate is that slope when positive. Doubling time is log(2)/rate. Lag is the OD-space tangent intercept with zero OD in the same selected window: mean_time minus mean_corrected_OD divided by the raw-OD OLS slope. Preserve negative lag; it is an extrapolated descriptor, not proof of a delayed biological phase. Nonpositive slopes leave affected descriptors unreliable. Time variance zero refuses as degenerate-window. Carrying capacity is explicitly the largest reliable observed corrected OD, never an asymptotic logistic estimate. Area is the trapezoidal integral over the entire supplied equal grid. Saturated points are never used for any descriptor in this conservative reference.

Synthetic A1 is generated by OD(t)=1/(1+4/2**t) at t=0..4, plus blank 0.05. Generator K=1, rate=log(2), midpoint=2; the chosen finite-window descriptor is not that logistic rate. Corrected OD is 1/5, 1/3, 1/2, 2/3, 4/5. The selected first three points give log(2.5)/2, tangent lag -35/27, observed maximum 4/5, AUC 2 and doubling 2*log(2)/log(2.5). A2 scales corrected OD by 3/4. A3 scales by 2 and saturates; noisy A4 has declared upstream non-convergence. These failed/negative controls remain present.

Failure: post-outcome-window for unlabelled window changes, saturation-capacity for a saturated carrying-capacity claim, unreliable-parameter for other retained unreliable descriptors, reported-number for arithmetic mismatch. Correct one recorded input defect in a new revision before retry; no automatic retries or method changes. Human decisions only for interpretation-changing revisions.

## 04-group-summary

Accepted identities: protocol, data and report hashes; parameter identities remain bound to original wells. Calls: `compute_growth_curve`. Output: group summaries in growth-result-v1 checked against growth-report-v1. Controls: group by strain and condition, use reliable wells for each parameter, retain well IDs and n and count distinct biological units. Technical wells remain technical. Below minimum_wells the mean and SE are unavailable, while n and exclusions remain visible. Otherwise mean is arithmetic mean and bootstrap-free SE is sample standard deviation divided by sqrt(n). Zero variance, including minimum/maximum values tied at the frozen relative tolerance with no absolute tolerance, leaves SE unavailable with reason zero-variance-uncertainty-unavailable and preserves the descriptive mean, avoiding apparent precision. No p-values or significance are computed.

Synthetic capacity mean is (0.8+0.6)/2=0.7, SE=0.1; AUC mean is (2+1.5)/2=1.75, SE=0.25. Each n is 2 technical wells from one biological unit. Saturated and non-converged wells are excluded. Failure: unreliable-summary for changed contributing IDs; technical-replication for inflated biological n or a biological replicate unit; reported-number for other discrepancies. No additional human gate.

## 05-handoff

Accepted identities: every input, report, evidence/source and controlling reference path/hash, plus captured result and execution/environment revision. Calls: `$science-provenance` ordinary artifact registration, existing separate claim-register records, `$science-review` record/source/method review. Output: growth-evidence-v1 and growth-result-v1 with review unavailable here; independent receipt and rigor classification belong to the coordinator. Controls: preserve dependencies, conflicts, failed controls, nulls, negative results, unavailable observations, exclusions, alternatives and limitations. The next falsifiable action is an independent check of the frozen measurement/subtraction/replication design, never a claim of actual fitness or mechanism from these fixtures.

Failure: claim-overreach, non-evidence-support, missing-evidence, unavailable-positive, unavailable-evidence, claim-replication, external-alias or generic input findings. Preserve refusal; never reinterpret a failed control as negative biological evidence. One checkpoint per run uses the five ordered IDs in the existing `{id,description,status}` plan shape. The pack adds no execution engine, MCP tool, global schema or payload key. Human gates occur only before installation, restricted transfer, new host, GPU/remote/heavy compute or an interpretation-changing choice. This route authorizes none of those actions.
