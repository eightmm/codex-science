# Plate-screen stages and local records

All distributed examples are synthetic fixtures. The public validator is `validate_hts_plate_qc_pack(path)` in `src/codex_science/hts_plate_qc_pack.py`. Run `python3 scripts/validate_hts_plate_qc_pack.py examples/workflow-hts-plate-qc/pack.json`. One positional bundle argument is accepted, with no output option. Successful JSON goes to stdout with exit 0; a labelled JSON refusal goes to stderr with exit 2. The validator writes nothing and never marks a result reviewed.

## Input safety and bounds

Every input is untrusted. Pin the absolute bundle root by walking each directory with O_DIRECTORY/O_NOFOLLOW descriptor-relative opens, lstat/fstat identity checks and a final visible-root comparison. Open artifact components relative to the pinned root, refusing symlinks, absolute/noncanonical paths, parent components, backslashes and control characters. Refuse FIFO, directory, device, missing, changed or growing files. Read a bounded snapshot, hash exactly the parsed bytes, cache by device/inode, parse each physical artifact once, then reread unique physical files solely to verify hashes and root identity at the end. Hardlink aliases share the parse and aggregate byte budget. Concurrent readers do not write; interruption leaves no validator artifact. A changed input or replaced root refuses rather than accepting a mixed snapshot.

Named module limits are MAX_BYTES=64 MiB per input, MAX_TOTAL_BYTES=256 MiB aggregate raw snapshots, MAX_TOTAL_NODES=4,000,000 JSON values per bundle, MAX_DEPTH=32, MAX_TEXT=4096 characters, MAX_ITEMS=20000 per JSON container, MAX_PLATES=128, MAX_WELLS=1536 per plate/grid/control list, MAX_ROWS=100000 total signal wells and per result list, MAX_CLAIMS=128, MAX_RECORDS=512 artifacts/support entries, and MAX_NUMBER=1e100 absolute numeric magnitude. JSON node tokens are counted before json.loads allocates the tree; strings and containers are bounded before domain loops. Plate lists, well lists and aggregate wells are bounded before building indexes. Rows are 2..26 and columns 2..MAX_WELLS with product at most MAX_WELLS. All numbers are finite and bool is never a number. Every declared integer (rows, columns, replicate IDs/counts, minimum counts) must be a real int, not bool, float or string. Refuse duplicate JSON keys at any depth, non-object roots, NaN/Infinity, huge integers, deep nesting and malformed UTF-8. No seed or numeric schema-version field exists in these local records; version is part of each schema name.

## Pack-local schemas

Every local record has exactly the fields below, with `schema` equal to its named version and `fixture: true`. This implementation admits synthetic fixtures only; real-study adaptation needs a separately reviewed method. Identities are objects `{path, sha256}`: canonical relative path and lowercase 64-hex hash, checked against the bundle. No existing global schema, receipt, claim-register or manifest field changes.

- **hts-pack-v1:** schema, fixture, stages (the five exact ordered IDs), frozen_layout (identity), inputs (exactly layout, signals, reported identities), exploratory (boolean), study_outputs (identity list, possibly empty), claims (possibly empty). All study outputs must be registered for identity comparisons. The freeze and current layout are parsed before signals; changes require exploratory true. This binds content and cannot prove when a human saw outcomes.
- **hts-layout-v1:** schema, fixture, rows, columns, assay, instrument, positive_controls, negative_controls, solvent_controls (disjoint canonical well lists, solvent nonempty), edge_rule (exclude/flag), minimum_z_prime (-10..1), minimum_ssmd (absolute minimum, nonnegative), maximum_drift (nonnegative signal units), hit_threshold (strictly positive), direction (higher/lower), replicate_requirement (1..MAX_ROWS), minimum_controls (2..MAX_WELLS per positive/negative set), minimum_samples (3..MAX_WELLS), baseline (all-samples). Positive and negative sets each span at least two rows and two columns. Wells use one uppercase row letter and unpadded positive column, such as A1; each lies inside the grid.
- **hts-signals-v1:** schema, fixture, assay, instrument, plates. Each plate has exactly plate_id and wells; each well has well_id, sample_id, replicate_id, value, observed. Plate IDs and plate-well pairs are unique. Every grid well and all three control sets must be present on every plate. Sample IDs are nonempty text; sample replicate IDs are positive integers and unique per sample across all plates. Controls may use replicate ID zero. Value is a finite supplied signal; observed must be true. Null and declared missing values filled with zero are refused. A genuinely observed zero signal is allowed. Assay/instrument equal the frozen identities. These declarations cannot detect dishonest, undeclared zero filling upstream.
- **hts-evidence-v1:** schema, fixture, kind, result, origin, sample_id. Origin is study/external/independent/preregistered. For a positive claim, require kind screening-evidence, result screening-signal and matching sample_id; review-approval and computed/numerical agreement in either field cannot support a positive claim. Declared external/independent/preregistered paths or hashes matching any known own input/output are refused, including bundle entry and frozen layout. Labels and distinct hashes still do not prove scientific independence.
- **hts-result-v1:** schema, fixture, plates, hits, replicates. Each plate has plate_id, status (passed/failed), z_prime, ssmd, signal_to_background (null when undefined), drift, drift_flagged (boolean), reasons (code list), median, mad (null when uncomputable). Each hit has plate_id, well_id, sample_id, replicate_id, robust_z, edge. Each replicate aggregate has sample_id, agreeing_replicates (real int), mean_signal, contributors (plate_id/well_id objects). The reported input uses exactly this shape. The computed public return also contains stages, evidence_level (screening-signal-only), review (unavailable), exploratory, claims, input_identities and limitations. Its input_identities include the bundle and every parsed artifact. Reported identities, flags, types, counts, numbers, ordering and contributor lists must match recomputation; float equality uses rel_tol=abs_tol=1e-10.

The pack's local claims have exactly id, kind, text, status, support (identity list), sample_id. IDs are unique, nonempty bounded text. Kind is descriptive/associational. Status uses existing planned/supported/replicated/suggestive/conflicting/unsupported/withdrawn/unavailable names; this local representation is an ordinary domain record, not a replacement global claim-register schema. Positive status requires a recomputed replicate-agreed hit; exploratory positives remain suggestive. Replicated is always refused for this single synthetic study. Empty support requires unavailable. Any citation whose kind or result is unavailable requires unavailable, even when mixed with observed evidence and for every other status. Unavailable text cannot assert supported, replicated, suggestive or significan\w* evidence.

## 01-freeze: layout and rules

Accepted identity: original layout path plus hash and current layout path plus hash. Call the local validator for structural checks and `$science-provenance` for the coordinator-owned immutable handoff. Output artifact: layout.json, hts-layout-v1; retain a distinct original when changed. Freeze all layout fields before the signal table is read, including format, every control well, edge rule, all limits and replicate requirement. Failure: missing control sets, overlap, one-row/column controls, malformed or degenerate counts stop admission. A threshold or edge change needs an exploratory label and retained freeze. Human gate: only an interpretation-changing choice or otherwise unauthorized installation/transfer/host/compute.

## 02-inventory: signal identity

Accepted identities: admitted layout path/hash and signals path/hash. Call the local validator; no network or instrument calls. Output: unchanged signals.json, hts-signals-v1, and normalized identity inventory in the result. Check every plate has the frozen controls, full grid, assay and instrument, distinct sample replicates and observed finite signals. No silent missing-to-zero coercion. Failure: refuse labelled input defect and preserve original signal table and failed run. No routine human gate; stop for an essential identity ambiguity.

## 03-qc: control metrics and position

Accepted identities: layout and signals path/hash. Call `control_metrics(positive, negative, minimum=2)` and the validator. Use sample standard deviation (ddof=1): Z′ = 1 - 3(sd_p + sd_n)/abs(mean_p - mean_n); signed SSMD = (mean_p - mean_n)/hypot(sd_p,sd_n); signal/background = mean_p/mean_n. Either control variance zero, equal means or zero negative mean is uncomputable and cannot pass. Require Z′ >= minimum_z_prime and abs(SSMD) >= minimum_ssmd, with equality passing. Negative-control row medians and column medians are calculated for rows/columns having controls; drift is the larger median range. Flag when drift > maximum_drift, equality unflagged. Drift alone is a positional warning, not automatic plate failure. This sparse check cannot assess rows without controls; independent review must assess layout fitness.

Output: complete QC in hts-result-v1. Preserve failed plates and metric/null reasons; no hit or replicate mean may use a failed plate. Failure codes distinguish undefined-zprime, positional-drift, failed-plate-hit and failed-plate-replicate. No new human gate for the frozen calculation.

## 04-hits: robust scores and agreeing replicates

Accepted identities: layout, signals and QC/reported artifact path/hash. Call `robust_scores(values, minimum=3)` and the validator. Use all same-plate sample wells, excluding all control sets but including edges in the baseline: median m, MAD=median(abs(x-m)), z=(x-m)/(1.4826*MAD). Fewer than minimum_samples or zero MAD makes the plate failed. Higher direction requires z >= threshold; lower requires z <= -threshold. Edge exclude removes a well from calling only; flag permits it and sets edge true. No pooled cross-plate baseline. Replicate_requirement counts distinct agreeing sample replicate IDs from passing plates; disagreeing replicates remain in the immutable signals and do not enter the mean. A replicate mean averages only agreeing hit signals and lists all contributors; a failed plate never enters it. Within-screen replicate agreement is not independent-study replication.

Output: reported.json, hts-result-v1, checked against complete recomputation; final JSON also carries provenance and limitations. Retain nulls, failed controls, absent hits and exclusion reasons in the handoff. No new human gate except an interpretation-changing choice. Do not mutate rules after outcomes to recover hits without exploratory status.

## 05-handoff: bounded claims and independent review

Accepted identities: bundle, all inputs, ordinary domain outputs and local evidence path/hash. Use `$science-provenance` and `$science-review`, preserving one coordinator checkpoint and ordered stage IDs from plan.json. Register domain artifacts normally with separate claim-register entries, never as self-issued review receipts. Output: unreviewed screening-signal result and review packet; independent review and rigor remain coordinator responsibilities. A negative result and unavailable record are different, and failed controls remain visible.

Refuse overreach regardless of kind or claim status with a conservative, incomplete, case-insensitive English whole-word prefix check using \w*: caus*, mechanis*, therap*, clinic*, efficac*, effective*, treat*, cure*, prevent*, recommend*, prescri*, bind*, affinit*, inhibit*, activat*, regulat*, drive/drives/driv*, induc*. Additionally refuse activ* (activity/active), poten* (potency), truth and physical validity. This lexical check cannot recognize every paraphrase, language or implication; independent review must evaluate meaning. Association is never causality; computed agreement is never physical/clinical validity; a screening hit is never compound activity, potency, inhibition or mechanism; approval is never truth. Every positive claim checks both declared record kind and result. A missing record is unavailable, never negative evidence. Gate only interpretation-changing choices or installation, restricted transfer, new host, GPU/remote/heavy compute.

## Synthetic acceptance and concurrency

The two 6×6 fixtures deliberately are not 384-well evidence. Positive variance=4/3; negative variance=40/7, mean=12. P1 positive mean=100 gives Z′=0.8791423491915441 and SSMD=33.1483153540389; P2 mean=20 gives Z′=-0.32943415889301453. Drift=4 exceeds limit=3 on both plates. All-sample median=12 and MAD=2 give HIT z=48/(1.4826×2). Only P1 B3/C3 contribute, giving mean=60; P2 B3=999 is preserved and excluded. Negative-cases.json contains synthetic mutation recipes materialized into temporary bundles by individually named tests; every recipe has a distinct stated refusal code even where codes are shared for one boundary family. The benchmark freezes questions, criteria and CPU budgets. Files checked in are immutable examples, not run outputs. The validator and CLI perform no writes: concurrent calls return independent snapshots or labelled changed-input refusals, and a kill leaves no partial output file (stdout may be partial and must not be admitted as JSON). Owner-side artifact registration and checkpoint writes use existing provenance contracts.
