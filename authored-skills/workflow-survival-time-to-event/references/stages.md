# Survival time-to-event stages and pack-local record contract

Every checked-in input and expected output described here is a **synthetic fixture**. Output states statistical evidence only. These instructions are procedure, not clinical evidence or a review receipt.

## Invocation and immutable identities

Public entry points: `codex_science.survival_pack.validate_survival_pack(bundle)` and `compute_survival(cohort, protocol, groups=None)`. The latter validates in-memory pack-local protocol/cohort objects; the former admits files, checks the supplied report and evidence, rechecks every input and returns `survival-result-v1`.

```bash
python3 scripts/validate_survival_pack.py examples/workflow-survival-time-to-event/pack.json
```

The CLI accepts exactly one bundle JSON argument, writes no files and prints one JSON object. Success exits 0; labelled refusal exits 2 with `status="refused"` and `error`. `--help` describes the bundle argument. There is no output-path option. Failed controls remain in the immutable supplied artifacts and caller-captured refusal; the coordinator preserves both as ordinary artifacts. No automatic input repair or retry occurs.

An artifact identity is exactly `{path, sha256}`: a canonical relative POSIX path inside the bundle directory and a required lowercase 64-hex SHA-256 of the raw bytes parsed. Null source hashes are refused as `input-hash`; malformed identities may also fail strict JSON or record checks. Only the entry-point pack read is initially unhashed. Refuse absolute paths, backslashes, traversal, symlink components and escaping paths. Walk from the filesystem root component by component using `O_DIRECTORY|O_NOFOLLOW` and the pinned parent descriptor; compare lstat/fstat device/inode identities at each open. Use the final descriptor for artifact reads and repeat the descriptor walk at final recheck. Every file gets lstat regular-file validation, `O_NONBLOCK|O_NOFOLLOW` open, descriptor fstat, a bounded read and post-read identity checks. Cache initial bytes by device/inode as well as path, so hardlink aliases share bytes and budget. Final recheck reopens every admitted path and reads each distinct inode once to detect replacement or modification. Parsing and hashing use the same initial bytes. A kill or second concurrent call leaves the input files unchanged; computation is read-only and stdout can be incomplete if interrupted. Coordinators must capture stdout atomically if a durable artifact is needed.

Limits are module constants: `MAX_BYTES=67108864` (64 MiB per file), `MAX_TOTAL_BYTES=268435456` (256 MiB aggregate raw bytes across all distinct artifact inodes, including the pack, wrappers and sources), `MAX_ROWS=10000` (cohort rows and generic JSON container count), `MAX_RECORDS=128` (claims, evidence artifact descriptors, evidence records in total and references per claim), `MAX_STRING=4096` characters, `MAX_DEPTH=32`, `MAX_NUMBER=1e100` for generic numbers and at most `1e12` for follow-up/assignment times. Before reading a new artifact, its fstat size plus admitted bytes must fit the aggregate budget; equality passes, excess is `input-limit`. Rechecks do not consume the budget again. Bounds apply before sets, per-item work or allocations proportional to those dimensions. Cohort rows and evidence/claim collections must be real lists; rows cannot be empty, while claims and evidence lists may be empty. Identity strings are nonempty and bounded. Strict JSON refuses duplicate nested keys, non-object roots, non-finite numbers, huge numbers, invalid UTF-8 and excessive nesting with labelled errors. Numeric fields reject booleans; every declared integer is a real int, never float or numeric string. Input and protocol errors are ValueError findings, never a CLI traceback.

## Pack-local schemas

These six schemas are local domain records registered as ordinary artifacts. Never insert their fields into existing manifests, receipts or claim-register sidecars. Object fields below are exact; unknown/missing fields are refused. All input records carry `fixture="synthetic fixture"` and the named `schema` string. A fixture does not attest a real observation.

- **survival-pack-v1**: `protocol`, `cohort`, `report` artifact identities; `evidence` list of evidence-record artifact identities; `frozen_protocol_sha256` equal to the protocol raw-byte hash; `frozen_before_table_read` real boolean true. The declaration is checked before the cohort is opened. The pack's parent is the bundle root.
- **survival-protocol-v1**: nonempty `time_origin`, `event_definition`, `censoring_rule`, `group_assignment`, `time_unit`; `groups` exactly two unique nonempty labels; `tie_handling="events-before-censoring"`; `test="log-rank"`; real `alpha` in [1e-12,0.5]; integer `minimum_events` and `minimum_subjects_per_group` in [2,MAX_ROWS]; real `maximum_censoring_imbalance` in [0,1]. These are fixture bounds, never power calculations. Group labels may contain spaces.
- **survival-cohort-v1**: nonempty `rows`. Each row is exactly `{subject_id, time, event, censored, group, group_assignment_time, time_unit}`. Subject identity is unique across both groups. `time` is finite, positive and at most 1e12; integer `event` is 0 or 1; real boolean `censored` equals `(event==0)`; `group` is one of the admitted labels. Assignment time is finite in [-1e12,1e12] and at most zero, representing the latest information used to assign the group, not just the date someone typed the label. Unit must exactly equal the frozen unit. There is no silent conversion, exclusion or deduplication.
- **survival-report-v1**: `protocol_sha256`, ordered `groups`, `test`, real booleans `exploratory` and `significant`, `medians` mapping each group to its first time at S<=0.5 or string `unavailable`, `censoring_fractions` mapping each group to its censored fraction, `hazard_ratio={value,label,proportional_hazards_claim}`, `headline` and `claims`. Hazard-ratio `label` is exactly `exploratory log-rank O/E hazard ratio`, its boolean proportional-hazards claim is false and `value` is the reference value or `unavailable`. Numerical reports must agree with the reference (relative tolerance 1e-9, absolute 1e-12). A post-hoc group/test change requires `exploratory=true`. Reversing the two groups is supported; alternative tests remain refused as `unsupported-test` even if exploratory, because no alternative calculation is implemented. An alternative group not present in the supplied table is unavailable, never reconstructed.
- **survival-evidence-v1**: `records`, each exactly `{id,kind,result,origin,source}`. IDs are unique across all evidence records. `kind`, `result` and `origin` are strings; `origin` is internal, external, independent or preregistered. `source` is a path-plus-hash identity. Read and hash the actual source, even when external. Non-internal evidence cannot alias the path or raw-byte hash of the pack, protocol, cohort, report or evidence wrappers; a renamed copy is still refused. This is a necessary anti-circularity check, never proof of real-world independence.
- **survival-result-v1**: `schema`, `fixture`, `status="statistical-evidence-only"`, `review="unavailable"`, ordered `stages`, `exploratory`, `inputs` containing all actually admitted paths/hashes, `computation`, checked `claims` and `limitations`. `computation.groups` maps labels to `{curve,median,subjects}`. Each curve row has `time`, `at_risk`, `events`, `censored`, `survival`, `greenwood_variance`, `log_log_interval`. `computation` also includes `censoring_fractions`, `significant`, `log_rank={observed,expected,variance,chi_square,p_value}` and the exploratory `hazard_ratio` object. This output is never self-reviewed or evidence of physical validity.

Report `claims` are **pack-local proposals**, not new fields in the existing claim register: exactly `{id,kind,status,text,evidence}`. Kind is descriptive or associational; statuses are planned, supported, replicated, suggestive, conflicting, unsupported, withdrawn or unavailable. `evidence` contains unique IDs from admitted evidence records. An empty evidence list requires unavailable; unknown evidence IDs are refused. All strings used as keys/statuses are validated before membership tests.

If any cited record has kind or result `unavailable`, the claim must have status `unavailable`; positive and negative interpretations are refused as `unavailable-evidence`. A `replicated` claim requires at least two cited source paths and two source hashes, with at least one declared non-internal source that passes the existing path/hash anti-alias checks; otherwise it is refused as `claim-replication`. The single internal cohort cannot establish replication. These declarations do not establish real-world independence or replace independent source/method review.

Every positive status (supported, replicated, suggestive) is refused if either the cited record's kind or result contains review, approv, comput, numer, agreement, truth, physical or clinic (case insensitive). This intentionally rejects review approval and computed agreement even if another label says observational. An unavailable claim cannot assert supported, replicated, suggestive or significan* evidence. Claims/headlines with hazard ratio or HR wording must contain the whole word exploratory.

The English wording gate refuses these whole-word prefix families (case insensitive; `*` means `\w*`): caus*, mechanis*, therap*, clinic*, efficac*, effective*, treat*, cure*, prevent*, recommend*, prescri*, bind*, affinit*, inhibit*, activat*, regulat*, drive/drives/driv*, induc*. It also refuses truth, physical validity and patient benefit. The gate applies to all claim texts and headlines regardless of their declared kind or status and includes negations. It is conservative and incomplete: unlisted paraphrases require independent source/method review. Association is never causality; computed agreement is never physical or clinical validity; review approval is never truth; missing records are unavailable, never negative evidence.

## 01-protocol: freeze and question

Accepted identities: bundle path/hash and `protocol.path` plus `protocol.sha256`. Calls: `$cx-statistical-decision-analysis` for the decision contract, `validate_survival_pack` for protocol admission and `$science-provenance` for ordinary artifact registration. Output: immutable `survival-protocol-v1` and the frozen identity in `survival-pack-v1`. Controls: all protocol fields above, fixed before reading outcomes; preserve original groups and test across exploratory revisions. Failure: `protocol-freeze`, `tie-handling`, `unsupported-test`, `invalid-record` or input findings; retain refusal and stop. Human gate only for an interpretation-changing choice or the external actions listed below. Hashes attest bytes, not preregistration history.

## 02-cohort: table and identity

Accepted identities: the unchanged frozen protocol and `cohort.path` plus `cohort.sha256`. Calls: `validate_survival_pack`, no extraction tool or download. Output: admitted `survival-cohort-v1`, preserved as supplied. Controls: subject identity, group membership, units, strict types and bounded rows. Failure: `duplicate-subject`, `group-identity`, `event-censoring`, `mixed-time-units`, `invalid-time` or input findings; do not repair. Human gates are unnecessary for admitted offline input.

## 03-integrity: leakage and censoring

Accepted identities: protocol and cohort raw-byte hashes. Calls: `compute_survival` integrity checks via the validator. Output: subject/event denominators and measured censoring fractions in `survival-result-v1`, or a preserved refusal. Controls: no assignment information after baseline; frozen subject/event minima; absolute difference of censored fractions <= frozen maximum. Equality passes; zero threshold admits only balanced fractions. Failure: `immortal-time`, `insufficient-subjects`, `insufficient-events`, `censoring-imbalance`. Even a nonsignificant run below the frozen event minimum stops this route. Balanced fractions do not establish noninformative censoring. Retain failures, nulls and unavailable evidence; ask only before an interpretation-changing revision.

## 04-computation: statistical evidence

Accepted identities: protocol, cohort, supplied report and evidence wrapper/source paths and hashes. Calls: the local standard-library `compute_survival` and `scripts/validate_survival_pack.py`; no external executable or installation. Output: checked `survival-report-v1`, admitted `survival-evidence-v1` and unreviewed `survival-result-v1`. Controls: two unpaired groups, one right-censored endpoint, no delayed entry or competing events; exact frozen tie rule, test and alpha; all declared numbers checked without selecting favorable results.

For each distinct time, risk is counted before tied events and censorings; S is multiplied by `(n-d)/n`. Greenwood variance is `S^2 * sum[d/(n*(n-d))]`. At S=0 the boundary variance is zero with interval [0,0]; at S=1 interval is [1,1]. Otherwise a normal quantile at `1-alpha/2` gives log-log CI using SE `sqrt(sum)/abs(log(S))`. Report the first time S<=0.5 as median; if never reached, median is unavailable, including an all-censored group. A ratio with a zero observed/expected component is unavailable rather than infinite.

Log-rank uses pooled tied events, `E_A=d*n_A/n`, `V=sum[n_A*n_B*d*(n-d)/(n^2*(n-1))]`, omitting the n=1 variance term. The one-degree-of-freedom statistic is `(O_A-E_A)^2/V`, and the two-sided p-value is `erfc(abs(O_A-E_A)/sqrt(2*V))`. Refuse V<=0 as `degenerate-log-rank`. Exploratory O/E hazard ratio is `(O_A/E_A)/(O_B/E_B)` and never a Cox estimate, causal effect or proportional-hazards claim. The tiny synthetic fixture derives E_A=5/6, V=17/36, chi-square=1/17, O/E ratio=13/10; tests derive these independently. No power or independent replication is established by the planted p-value.

Failure findings include `median-unavailable`, `reported-number`, `significance-mismatch`, `hazard-label`, `hazard-unavailable`, `post-hoc-change`, `claim-overreach`, `non-evidence-support`, `missing-evidence`, `unavailable-positive`, `unavailable-evidence`, `claim-replication`, `external-alias` and generic input findings. Preserve controls and refusal, never relabel a failure as negative evidence. No further human gate for this admitted offline route.

## 05-handoff: claims and independent review

Accepted identities: every input and reference path/hash plus the captured result, logs and claims. Calls: `$science-provenance` ordinary artifacts, separate existing claim-register entries and `$science-review` record/source/method modes. Output: the coordinator's ordinary artifact and claim records; only the coordinator can classify rigor and register an independent review receipt. Controls: keep review unavailable here, distinguish computational checks from scientific acceptance and retain all failed/null results, dependencies, conflicts, rejected alternatives and unavailable observations. The smallest next action is a source-backed independent review of the frozen endpoint, assignment timing and censoring assumptions; change the method only under a new documented exploratory revision. Approval is never truth.

One checkpoint per run uses ordered stage IDs from `plan.json`; its plan entries reuse `{id,description,status}` exactly. Never add new global receipt, manifest or checkpoint keys. Human gates occur only before installation, restricted transfers, new hosts, GPU/remote/heavy compute or an interpretation-changing choice. The reference authorizes none of those external actions. All runtime writes are owned by the coordinator; this validator writes no records, refs or files, so concurrent calls and interruptions cannot partially publish them.
