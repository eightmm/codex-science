# Replicate peak QC: stages and pack-local records

All checked-in data are synthetic fixtures, not biological evidence. Only the coordinator may classify rigor, register independent review receipts or complete a run. Use one checkpoint with ordered IDs `01-rules`, `02-intervals`, `03-qc-consensus`, `04-summary`, `05-handoff` and existing manifest steps `{id, description, status}`. Register domain records as ordinary artifacts and record claims separately in the existing claim register. No global schema changes.

## Invocation and immutable identities

Run `python3 scripts/validate_peak_replicate_qc_pack.py examples/workflow-peak-replicate-qc/pack.json`. The CLI takes one bundle JSON argument, writes nothing and prints JSON on stdout on success (exit 0). Refusals, including missing/extra/unknown arguments, are labelled JSON on stderr (exit 2); `--help` prints plain usage on stdout (exit 0). There is no output option. Programmatic entry points are `validate_peak_replicate_qc_pack(bundle)` and `compute_peak_qc(table, rules, blacklist)`; the latter validates supplied records but has no file identity handoff.

Every file identity is exactly `{path, sha256}`: canonical relative POSIX path, lowercase SHA-256 of the bytes parsed. Absolute paths, parent components, backslashes, symlinks and escaping components are refused. The root is pinned from the filesystem root with directory descriptors and `O_DIRECTORY|O_NOFOLLOW`; every ancestor's device/inode identity is compared again before and after final hash checks. Artifacts are opened relative to pinned descriptors using `O_NONBLOCK|O_NOFOLLOW`, lstat/fstat identity checks, regular-file and size checks and a bounded read. Distinct inodes are read/parsed once for admission, hardlink aliases share their cached data, and a second bounded read per inode rechecks hashes before return. Changed or growing inputs are refused. Concurrent validator calls write no files. A kill at any point leaves no partial artifacts.

## Bounds and malformed input

Module constants: `MAX_BYTES` 64 MiB per file; `MAX_TOTAL_BYTES` 256 MiB aggregate distinct input bytes, enforced from descriptor size before reading; `MAX_TOTAL_VALUES` 4,000,000 bundle JSON values via a preparse upper bound, enforced before `json.loads`; `MAX_ARTIFACTS` 128 paths; `MAX_REPLICATES` 16; `MAX_CHROMOSOMES` 64; `MAX_PEAKS` 20,000 total supplied peak and blacklist intervals; `MAX_RECORDS` 128 claims/evidence/support names; `MAX_ITEMS` 40,000 entries per JSON container/reported consensus; `MAX_STRING` 4,096 characters; `MAX_DEPTH` 32; `MAX_INTEGER` 10^12 for read counts, coordinates and chromosome lengths; `MAX_NUMBER` 10^100 for other finite numbers. Bounds are checked before dimension-dependent sets, pair construction, sweeps and event allocation. Counts are real integers, never bools, floats or strings, including schema versions and report counts. Duplicate JSON keys (nested too), non-object roots, NaN/Infinity, excessive depth, huge numbers and wrong types are labelled refusals. Zero library totals are refused. Empty available peak sets have zero FRiP; both-empty Jaccard is `unavailable`, never a significant-looking number.

## Pack-local schemas

Every record has `schema` set to its listed name, real integer `schema_version: 1`, and `fixture: "synthetic fixture"`. Fields are exact; unknown/missing keys are refused. These are local shapes only.

- `peak-qc-pack-v1`: `rules`, `peaks`, `report`, `evidence` identities; `frozen_rules_sha256`; boolean `frozen_before_peaks_read`. Load and hash rules and blacklist before opening peaks. The declared freeze is not proof of historical order.
- `peak-qc-rules-v1`: nonempty `genome_build`; nonempty `chromosomes` map from names to positive lengths; unique `replicates` list (2–16); positive integer `minimum_reads`; fractions `minimum_frip`, `minimum_replicate_overlap`, `reciprocal_interval_fraction` in [0,1]; `blacklist` identity; boolean `input_control_required`; `peak_merge_rule: "supported-segments"`; integer `minimum_support` from 2 to the design size. Safe alternative merge rules require a separately reviewed implementation.
- `peak-qc-blacklist-v1`: `genome_build`, `intervals`. Each interval is `{chrom,start,end}`, lexically sorted and non-overlapping, with real integer 0-based half-open coordinates `0 <= start < end <= chromosome length`. The set's path and hash are embedded in the frozen rules; empty blacklists are allowed.
- `peak-qc-peaks-v1`: `genome_build`, `replicates`. Each replicate has exactly `id`, `status`, `genome_build`, `total_reads`, `reads_in_peaks`, `input_control`, `peaks`. Every frozen replicate appears exactly once. For `available`, counts are integers, total positive, peak reads between 0 and total. Peaks are intervals plus a finite non-negative `score`. Empty peaks require zero reads in peaks. `input_control` is either `"unavailable"` (only if optional) or `{id,genome_build,total_reads}` with positive integer reads. For `unavailable`, both counts, control and peaks must all be the literal `"unavailable"`; zero or empty values are refused. At least two available libraries are required. All genome builds, including controls and blacklist, must equal the frozen build. A count/control declaration cannot prove how the experimental input was collected.
- `peak-qc-report-v1`: `rules_sha256`, `minimum_replicate_overlap`, boolean `exploratory`, `headline`, `computation`, `claims`. The rule hash always remains original. Only the overlap QC threshold may be varied, with `exploratory: true`; it is recomputed and the original rules retained. Unlabelled changes are refused. All other rule changes need a distinct freeze and run.
- `peak-qc-evidence-v1`: `records`, each `{id,kind,result,origin,source}`; unique IDs, nonempty string kind/result, origin one of internal/external/independent/preregistered, source identity required. Non-internal path or hash equality with any study input/output is refused **before** interpreting the source schema. Labels cannot establish independence.
- `peak-qc-source-v1`: `kind`, `result`, `note` strings. Both evidence record AND underlying source kind/result are checked for computed/review/unavailable evidence; a wrapper cannot promote its underlying source.
- `peak-qc-result-v1`: `status: "arithmetic-only"`, `review: "unavailable"`, ordered `stages`, boolean `exploratory`, input identities, `computation`, claims and limitations. The returned record is reference arithmetic, never a review receipt.

`computation` is exact: `n_replicates`, `n_available`, `n_eligible`, `n_pairs`, `n_consensus`, `replicates`, `pairs`, `consensus`. Replicate summaries: `{id,status,n_peaks,blacklist_peak_count,total_reads,reads_in_peaks,frip,eligible,flags}`. Unavailable counts/FRiP are literal `"unavailable"`, eligibility false, flag unavailable. Available flags are low-reads, low-frip and/or low-overlap. Pairs: `{first,second,n_first,n_second,intersection_bp,union_bp,jaccard,directional_fractions,reciprocal_overlap_fraction}`. Consensus: `{chrom,start,end,replicates,n_support}` with sorted identities. All integers must match the exact reference; fractions tolerate absolute/relative error 1e-12. Blacklist and excluded-support refusals precede generic report mismatch and wording gates, preserving each seeded refusal's stated reason.

Claims are exactly `{id,kind,status,text,evidence}` with unique string IDs, descriptive/associational kind, string status in planned/supported/replicated/suggestive/conflicting/unsupported/withdrawn/unavailable, and unique evidence-ID strings. Empty evidence requires unavailable. Any citation with kind or result unavailable (wrapper or source) requires unavailable, even mixed with observed evidence and for every other claim status. Unavailable text cannot assert supported, replicated, suggestive or significan*. Positive status supported/replicated/suggestive cannot cite any review/approval, computed/numerical agreement, truth or physical/clinical record; kind **and** result are checked. Replicated status is always refused because this fixture cannot establish independent replication.

Conservative English whole-word prefix families (case insensitive): caus*, mechanis*, therap*, clinic*, efficac*, effective*, treat*, cure*, prevent*, recommend*, prescri*, bind*, affinit*, inhibit*, activat*, regulat*, drive/drives/driv*, induc*. The gate additionally refuses enhanc*, promot*, truth, physical validity and patient benefit. It applies to headlines and claim text regardless of kind/status, includes negations and is incomplete for unlisted paraphrases. An association is never causality; numerical agreement is never physical or clinical validity; approval is never truth. Failed controls and negative results must be preserved.

## 01-rules: freeze before peaks

Input identities: complete rule path/hash and embedded blacklist path/hash. Call `$cx-statistical-decision-analysis` for threshold framing and `$science-provenance` for immutable identities. Output: `peak-qc-rules-v1` with all thresholds, design, genome and control requirements fixed before outcomes; coordinator stores its hash and original bytes. Stop for missing essential design or an interpretation-changing ambiguity. Preserve alternatives and failed revisions. No per-stage permission prompt.

## 02-intervals: identity and admission

Input identities: frozen rules/blacklist and peak table path/hash. Call the pack validator's `_intervals` and `$science-provenance`. Output: admitted `peak-qc-peaks-v1` and blacklist identities plus per-replicate original/blacklist counts in the result. Known chromosomes, half-open bounds, scores, sort order, non-overlap and build identity are controls. Refuse defects without normalization; a failed record remains an unavailable prerequisite, never negative evidence.

## 03-qc-consensus: exact sweep

Input identities: admitted peak table, rules and blacklist. Call `compute_peak_qc`. Output: `peak-qc-result-v1` computation. FRiP = supplied reads in original called peaks / supplied library total; removing blacklisted intervals cannot adjust read counts without read-level data, so the original denominator and numerator stay visible. Remove an entire peak if it overlaps any blacklist base (do not clip). Calculate pairwise intersection with a two-pointer sweep over clean disjoint intervals; union = covered bases A + covered bases B - intersection; Jaccard = intersection/union. Two peaks match only with positive intersection and intersection/length >= frozen reciprocal interval fraction **in both directions**. Directional fractions = matched peaks / clean peaks for each replicate (zero if empty); reciprocal-overlap fraction = their minimum.

Check **every available pair before exclusions**. A replicate fails overlap if any available partner's pair fraction falls below the minimum; this conservative choice avoids order-dependent iterative exclusion but a poor partner can exclude otherwise similar libraries. All failing libraries retain flags and are excluded. Exact equality passes thresholds. No eligible replicates or too few for support yields empty consensus, not an exception or a successful biological claim.

Consensus is an event sweep over eligible clean intervals: retain maximal adjacent half-open segments with identical replicate support and support count >= minimum_support. Split when the support identity set changes; never merge across gaps, across chromosomes or just by touching with changed support. At every segment, support lists the actual contributing eligible replicates. Blacklist-overlapping segments and failed-library support in supplied reports are distinct refusals.

## 04-summary: explicit n

Input identities: report path/hash plus previous handoffs. Call the validator to compare all report integers, fractions, exclusions, pair and consensus rows. Output: `peak-qc-report-v1` and read-only `peak-qc-result-v1` with denominators, uncertainty/limitations and claims. n refers to libraries/pairs/segments, never independent biological units. No interval count or FRiP threshold establishes enrichment significance. Preserve conflicting, negative and unavailable results; retry only after correcting the named defect, with immutable previous revisions.

## 05-handoff: coordinator review

Input identities: every admitted path/hash, report, evidence/source records, claim IDs, code and environment revision and reference-use ledger. Call `$science-provenance` and `$science-review`; keep separate claim-register entries under existing global contracts. Output: coordinator's review packet, not a pack-generated approval. Independent method/source/record review and rigor classification remain unavailable until performed by the coordinator. Next falsifiable action is inspection or acquisition of the flagged input/control. Human gates apply only before installation, restricted transfers, new hosts, GPU/remote/heavy compute or interpretation-changing choices; no such operations occur here.

## Synthetic fixture and failure acceptance

`examples/workflow-peak-replicate-qc/pack.json` pins a two-chromosome synthetic genome and three replicate records. A/B pass; C fails minimum reads and FRiP. A/B clean intersection is 15 bases, union 25, Jaccard 3/5, reciprocal overlap 1. FRiP is 1/2, 2/5, 1/10. Consensus is chrA:[15,20) and [40,50), support A/B. One blacklist peak in A and B is counted and removed. These values are checked independently in `tests/test_workflow_peaks_pack.py` rather than accepted from generated expected JSON alone. `negative-cases.json` is an executable mutation table; every case names its distinct required refusal code. Frozen budgets and questions are in `benchmarks/workflow-peak-replicate-qc/tasks.json`.
