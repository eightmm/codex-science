# ddPCR stages and pack-local record contract

Every checked-in table, question and expected artifact is a synthetic fixture. This reference controls software arithmetic only; it is neither observational evidence nor independent review.

## Invocation and immutable identities

Public entry points in codex_science.ddpcr_absolute_quantification_pack: validate_ddpcr_absolute_quantification_pack(bundle), compute_ddpcr(counts, rules, thresholds=None), exact_binomial_interval(positive, total, level=0.95). The thin CLI takes one bundle argument, prints JSON on stdout, writes nothing, and has no output option.

```bash
python3 scripts/validate_ddpcr_absolute_quantification_pack.py examples/workflow-ddpcr-absolute-quantification/pack.json
```

Every refusal is a labelled ValueError; CLI refusals are JSON on stderr with status refused, finding containing the labelled error and exit 2. Missing, extra and unknown arguments give invalid-arguments. Help remains plain usage on stdout and exit 0.

An artifact identity is exactly path and sha256, a canonical bundle-relative path and lowercase 64-hex SHA-256 of the bytes actually parsed. Refuse traversal, absolute artifact paths, backslashes, symlinked components, missing inputs, FIFOs, devices, directories, oversized and changing inputs. Walk the absolute root through O_DIRECTORY/O_NOFOLLOW directory descriptors from the filesystem root, retain each ancestor device/inode and pin the final descriptor. All artifact opens use dir_fd plus O_NONBLOCK/O_NOFOLLOW, lstat/fstat identity comparison and bounded reads. Initially read and parse each inode once, including hardlink aliases. At completion reopen through descriptors, rehash each inode once and recheck the entire ancestor chain before and after. A second concurrent validator writes nothing; termination between reads leaves no file or record changes. External mutation may cause a labelled refusal; these checks cannot establish a historical snapshot against arbitrary undetectable adversarial changes.

## Limits

MAX_BYTES is 64 MiB per file; MAX_TOTAL_BYTES is 256 MiB per bundle, charged from descriptor size before reading new inodes. MAX_ARTIFACTS is 256 path identities. MAX_NODES is 4000000 JSON values over unique parsed inodes. Enforce the remaining preparse upper bound as one plus comma count plus nonempty container count, using non-consuming lookahead and a streaming match iterator, before JSON allocation. Recount the parsed tree against the allowance. Conservative counting can overcount punctuation in strings.

MAX_ROWS is 10000 wells or entries per JSON container; MAX_SAMPLES is 128; MAX_RECORDS is 128 claims, evidence descriptors, evidence IDs per claim and total evidence records. Check list lengths immediately before sets, indexes or computation. MAX_STRING is 4096 nonempty nonsurrogate characters; MAX_DEPTH is 32; MAX_NUMBER is 1e100. MAX_PARTITIONS is 1000000 per well and per pooled sample, enforced before interval evaluation. MAX_ITERATIONS is 10000 beta fraction iterations; QUANTILE_STEPS is 96 bisection steps. Nonconvergence is binomial-convergence, never an approximate fallback.

All numeric inputs are finite, and all declared integers are real int values, never bool, float or string. Minimum accepted partitions and replicate wells are integers in 1 to MAX_PARTITIONS and 1 to MAX_ROWS respectively; NTC maximum is an integer in 0 to MAX_PARTITIONS. Saturation bound is in 1e-9 to 1-1e-9; agreement bound is in 0 to 1. Partition volume in uL is in 1e-12 to 1e6; dilution and reaction-to-sample multipliers are each in 1e-12 to 1e12. Confidence is in 0.5 to 0.999. Bounds are inclusive. Exact interval n must be positive, with 0 <= k <= n. A transformed upper endpoint must remain at least 1e-12 below one relative to the unit fraction; otherwise refuse singular-interval. Refuse nonfinite transformed quantities. JSON duplicate keys at every level, non-object roots, malformed UTF-8, NaN/Infinity, overflowing floats, huge numbers and excessive nesting are labelled refusals; overflowing floats specifically give invalid-json.

## Pack-local schemas

These six schemas are ordinary domain artifacts. Input records contain exactly schema equal to the named schema, fixture equal to synthetic fixture and the fields below; unknown or missing fields are refused. No existing record or receipt gains a field.

- ddpcr-pack-v1: rules, counts, report artifact identities; evidence list of artifact identities; frozen_rules_sha256 equal to rules.sha256; real boolean frozen_before_counts_read true. The freeze declaration is checked before count bytes are opened; a hash cannot prove historical order.
- ddpcr-rules-v1: unique nonempty sample_ids; nonempty wells; partition_volume_ul; minimum_accepted_partitions; ntc_maximum_positive; saturation_bound; dilution_factor; reaction_to_sample_scaling; confidence_level; interval_method clopper-pearson-exact; replicate_wells_per_sample; agreement_bound. Each well is exactly well_id, sample_id and role. IDs are unique. Role is sample or ntc; sample wells belong to the frozen sample list, while ntc wells use reserved sample_id NTC outside that list. At least one NTC and exactly the frozen number of wells for every sample are required.
- ddpcr-counts-v1: nonempty rows. Each row is exactly well_id, sample_id, role, flag, positive and total. Every frozen well appears exactly once with matching identities. Flag is observed or unavailable. Observed counts are integers in 0 to MAX_PARTITIONS and positive <= total; total zero is retained as inadequate partitions. Unavailable requires both counts null, never zero. An omitted NTC gives missing-ntc; other missing wells give missing-well and require explicit unavailable rows.
- ddpcr-report-v1: rules_sha256; real boolean exploratory; thresholds with exactly minimum_accepted_partitions, ntc_maximum_positive, saturation_bound, agreement_bound; interval_method; confidence_level; ordered wells; ordered samples; summary; nonempty headline; claims. Thresholds must match frozen rules under EDGE_TOLERANCE 1e-12 with zero absolute tolerance unless exploratory true, and the confidence level must always match its frozen value at that tolerance; the agreement and saturation decisions use the same tolerance at their inclusive bounds. Original rules/hash remain immutable. Exploratory thresholds must pass the same bounds; recompute all results. Method and confidence remain frozen. Boundary/evidence gates precede arithmetic so later errors cannot mask their findings.
- ddpcr-evidence-v1: records. Each record is exactly id, kind, result, origin, source. IDs are unique across all evidence documents. Kind/result are nonempty strings. Source is a hash-bound artifact identity. Origin is internal, external, independent or preregistered. Non-internal source path and hash must both differ from every pack, rule, count, report and evidence-document identity. Copies and hardlinks cannot establish independence. Non-aliasing alone does not establish independence.
- ddpcr-result-v1: validator-produced schema, fixture, status arithmetic-only, review unavailable, ordered stages, exploratory, inputs as path/sha256 identities, computation, claims and limitations. It is never a passed review receipt. Expected.json wraps computation with fixture; negative-cases.json lists synthetic mutations, target document/path, value or removal and expected finding. The optional refresh_wells flag refreshes individual-well results while retaining defective pooled sample values for the disagreeing-replicates case.

Computation is exactly wells, samples and summary. Every well is exactly well_id, sample_id, role, status, reason, positive, total, positive_fraction, lambda, concentration_copies_per_ul and interval. Status is quantified, unavailable or control-passed. NTCs always retain unavailable lambda, concentration and interval, even when control-passed. Unavailable wells preserve observed counts or nulls and their positive fraction when definable. All unavailable estimates and intervals are the literal string unavailable. Quantified interval is exactly method clopper-pearson-exact-transformed, level, lower, upper, in copies per sample-equivalent uL.

Every sample is exactly sample_id, well_ids, status, reason, positive, total, positive_fraction, lambda, concentration_copies_per_ul and interval. Positive/total are pooled integers only when all counts are observed, otherwise unavailable. Preserving sums on a failed sample does not admit their quantification. Summary is exactly integer n, quantified, unavailable; boolean ntc_passed; mean_concentration_copies_per_ul or unavailable. n counts frozen samples, not technical wells. Compare every reported numeric value with recomputation using relative tolerance RELATIVE_TOLERANCE 1e-8 and zero absolute tolerance; integer types remain strict. Distinct near-zero values do not become ties. Strings, booleans, nulls, identities and selection order must match exactly.

## 01-rule-freeze

Input: coordinator decision, assumptions, sample/well identities and intended claims. Call $cx-statistical-decision-analysis for uncertainty framing and $science-provenance for rules.json path/hash registration as ddpcr-rules-v1. Output: immutable rules identity, existing manifest step and one coordinator checkpoint. Freeze volume, partition minimum, NTC maximum, saturation, dilution/scaling, exact interval/level, replicate count and agreement before outcomes. Stop on essential ambiguity. Later interpretation-changing choices need a human decision and exploratory labelling, with original revisions preserved. No routine per-stage gate.

## 02-count-qc

Input: rules and counts.json path/hash identities. Call the validator's identity/type/QC checks. Output: admitted ddpcr-counts-v1 ordinary artifact, retaining failed controls and explicit unavailable counts. Check unique wells, nonnegative real integer counts, positive <= total, total >= minimum, NTC presence and positives <= NTC maximum. Equality passes. Missing NTCs refuse admission; failed or unavailable NTCs leave every sample and sample well unavailable. Never interpret a failed NTC as negative evidence.

## 03-quantification

Input: admitted counts/rules identities and declared thresholds. Call compute_ddpcr and exact_binomial_interval through the one-argument CLI. Output: per-well and pooled sample records in ddpcr-report-v1 and ddpcr-result-v1. For each observed sample well with enough partitions, p = k/n. If p = 1 return unavailable with singular-positive-fraction; if p exceeds saturation return unavailable with saturated-well. Inadequate partitions give insufficient-partitions; missing counts give missing-counts. An NTC exceeding its maximum gives ntc-contamination; any NTC failure propagates ntc-failure to sample wells. Reported numerical estimates in these states are refused, never zeroed.

For passing wells, lambda = -log1p(-p), concentration = lambda times dilution_factor times reaction_to_sample_scaling divided by partition_volume_ul. At confidence L and tail t = (1-L)/2, exact positive-fraction lower is BetaQuantile(k,n-k+1,t) for k > 0, otherwise zero; upper is BetaQuantile(k+1,n-k,1-t) for k < n, otherwise one. The implementation evaluates regularized incomplete beta continued fractions with log-gamma factors and bounded bisection, using tail symmetry. Endpoint k=0 upper is -expm1(log(t)/n); k=n lower is exp(log(t)/n). No normal approximation. Transform both fraction endpoints monotonically by -log1p(-p) and the same scale. For zero positives the estimate is zero but the upper concentration is strictly positive, -log(t)/n times scale; this is not proof of absence.

Pool all technical wells for a sample only when every well passes and (max(lambda)-min(lambda))/max(lambda) <= agreement_bound. All-zero wells agree without division. Equality passes. Disagreement gives unavailable pooled concentration and reason replicate-disagreement; individual estimates and counts remain visible. Sum integer positive/total counts for pooling; do not average per-well concentrations. Technical wells are neither independent samples nor replication. Compute one exact binomial interval for the pooled totals. Equal-volume independent partitions and accurate volume/scaling remain unverified assumptions. Selection and calibration uncertainty are outside these bounds.

## 04-summary

Input: all well/sample results and original identities. Call the reference summary checks. Output: sample n, quantified/unavailable counts, NTC status and quantified-only mean in ddpcr-report-v1. Use math.fsum for the mean. With no quantified samples the mean is unavailable. Preserve zero counts, failures, negative results, nulls, conflicts, rejected choices and sensitivity needs; do not discard a failed well to obtain agreement.

## 05-handoff and claim gate

Input: report/evidence identities, rules, counts, failures and coordinator records. Call $science-provenance for ordinary artifacts plus separate existing claim-register entries and $science-review for independent record, source and method review. Output: ddpcr-result-v1 and the coordinator's existing checkpoint, claim register and later independent receipt. This pack never marks its output reviewed. Preserve refusal JSON and original failed revisions with their hashes.

Claims are exactly id, kind, status, text and evidence IDs. Kind is descriptive or associational. Status is planned, supported, replicated, suggestive, conflicting, unsupported, withdrawn or unavailable. Empty evidence requires unavailable. Any unavailable kind or result requires unavailable for every other status, even mixed with observed evidence. Unavailable text cannot assert supported, replicated, suggestive or significant evidence. Replicated always refuses: this synthetic fixture cannot establish two independent studies. Every positive status refuses a citation whose kind OR result denotes review, approval, computation, numerical agreement, truth, physical or clinical validity. Kind labels never bypass wording checks.

The conservative case-insensitive English whole-word/prefix wording families are: caus*, mechanis*, therap*, clinic*, efficac*, effective*, treat*, cure*, prevent*, recommend*, prescri*, bind*, affinit*, inhibit*, activat*, regulat*, drive/drives/driv*, induc*. Also refuse truth, physical validity, patient benefit, copy-number, gene dosage, disease* and sample suitability. Space or hyphen separators are equivalent for multiword gates. The lexical check includes negations and is incomplete for other paraphrases and languages. Association is never causality; computed agreement is never physical or clinical validity; absence of a record is unavailable, never negative evidence; review approval is never truth.

Human gates apply only before installation, restricted transfer, a new host, GPU/remote/heavy compute or an interpretation-changing choice. This route performs no such compute, transfer, installation or networking. Independent review and interpretation remain coordinator-owned; approval cannot turn evidence into truth.
