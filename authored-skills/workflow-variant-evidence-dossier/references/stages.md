# Fixed stages and pack-local records

These are pack-local record schemas, registered as ordinary artifacts. They do not add fields, artifact kinds, receipts, checkpoint states or payload keys to any existing global contract. SHA-256 always means the digest of exact file bytes, not reserialized JSON. Fixtures are synthetic, redistributable under MIT, and contain no patients or real clinical assertions.

## Shared acceptance and handoffs

Use the existing manifest `plan` array from `plan.json` and one coordinator checkpoint per run, ordered `01-normalize`, `02-retrieve`, `03-reconcile`, `04-bound-claims`, `05-review-handoff`. Inputs to every stage are immutable run-relative paths plus SHA-256 registered by the existing provenance flow. Domain files use ordinary artifact registration; claims additionally receive separate entries using the existing claim-register schema. Do not put new domain keys inside existing sidecars. The final stage records delivery to the coordinator, never completed independent review.

Before outcomes, fix the question, genome build, allele, transcript, phenotype, population, cutoff, positive/negative controls, denominator units, source/dependency rules, uncertainty, falsifier and follow-up. A descriptive source observation needs a retained identity-matched record. Association needs explicit association evidence, never gene/trait indexing. Positive support needs observed rows and all controls passed. Replication needs at least two selected sources, disjoint known cohort AND dependency groups, aligned estimands and independent method review. Do not derive independence from source count alone. Unknown groups are written `unknown` and cannot support replication.

## 01-normalize

Accepted input: the supplied public variant file and its path/hash; declared organism, build, coordinate convention and transcript. Calls `$cx-variant-evidence-synthesis` and its identity reference, using existing dbSNP/Ensembl skills only for their supported lookup operations. No normalization code, liftover engine or remote execution is added by this pack.

Output: frozen `identity-ledger.normalized.json`, schema `variant-identity-ledger-v1`, containing `identity` and an empty `sources` list. Required `identity` contains `genome_build`, `chromosome`, positive integer one-based `position`, uppercase explicit DNA `ref` and `alt`, forward `strand` (`+`), and `transcript` including version when available. Transcript-independent scope must be an explicit recorded label, never a fabricated accession. REF and ALT differ. This immutable normalization-stage input is retained when stage 02 builds a separate completed ledger; the final dossier validator refuses an incomplete ledger as its final input.

The completed stage-02 `identity-ledger.json` uses the same schema and canonical identity, with `normalization_input: {path, sha256}` linking that frozen stage-01 file. Its `sources` contains exactly one entry per `clinvar`, `gnomad`, `dbsnp`, `gwas_catalog`, `ensembl`, including unavailable sources. Each entry has `source`, `snapshot: {path, sha256}`, selected `record_id`, `identity_pointer` (JSON pointer into its saved snapshot), and `reconciliation` (`identity` or `reverse-complement`). A no-record snapshot uses null record ID and pointer. Source identities retain the same identity fields. A source identity must actually be present in the retained snapshot; no guessed identity from the query. Reverse complement changes both REF/ALT and strand, retaining locus/build/transcript; a mere swap or unresolved palindromic ambiguity cannot pass.

The identity pointer must start with `/records/N/`, where N selects the ledger's `record_id`; another record's identity cannot be borrowed. The synthetic fixtures use artificial normalized record objects containing a `variant` identity for testing; these are not representations of live provider responses. Existing adapters can lack these fields. If no returned object supplies a verified identity, keep that lane unavailable with null `record_id` and `identity_pointer` and retain its returned data for independent review; do not manufacture a `variant` field in a live connector snapshot. A real dossier may need a source-native identity-bearing record or a supported public lookup first. The validator does not implement source-native annotation parsing or prove that normalization is biologically correct.

Controls: normalize the positive and negative control identities under the same build/transcript convention. Failure: stop allele synthesis on mismatch or unresolved mapping, preserve originals. Human decision gate: only an interpretation-changing build, allele or transcript choice; no routine stage approval.

## 02-retrieve

Accepted input: frozen identity ledger and protocol path/hash; source query plan and controls. Calls the five existing retriever skills named in SKILL.md and their selected references. Use only the connector's documented operation and parameters; source gene or trait search cannot be upgraded into variant evidence. Request a saved connector snapshot through the existing v2 route and validate it by `codex_science.connector_contract.replay_snapshot`; `scripts/replay_connector_snapshot.py` is the existing replay CLI. Tests replay only checked-in fixtures and never contact providers.

Outputs: completed `identity-ledger.json` with unchanged frozen identity and its normalization input path/hash; original connector snapshots with unchanged schema (request, records, receipt, pages), access time, reported release, exact query, truncation, exclusions and failure status, bound through ledger snapshot `{path, sha256}`. Never rewrite the stage-01 file. The connector may label an empty successful result `negative` in its receipt; preserve the receipt unchanged and translate the dossier row to `unavailable`. A failed or partial request cannot support an observed row. No matches and no reported release are not evidence of absence or freshness. When a normalized-only fixture is used, disclose that raw transport was not tested.

Controls/threshold: bounded smallest supported query and frozen positive/negative control pair, one identical retry for a transient error. Retain both attempts. Failure: preserve unavailable/partial source plus reason; no silent alternate host or download. Gate only before installation, restricted transfer, a new host or remote/GPU/heavy compute; record already granted source terms and permissions once.

## 03-reconcile

Accepted input: frozen ledger, all connector snapshots and optional supplied burden/PheWAS/locus records, each with path/hash. Calls `$cx-variant-evidence-synthesis`; select `$cx-locus-to-gene-prioritization`, `$cx-gene-burden-evidence` and `$cx-phewas-replication-analysis` only within their existing method contracts. Their unchanged schemas remain separate ordinary artifacts.

Output: `evidence-table.json`, schema `variant-source-evidence-v1`, `rows` with exactly one row per planned source. Each row requires `source`, ledger-matching `record_id`, `status` (`observed`, `negative`, `unavailable`), `evidence_type` (`identity`, `annotation`, `association`, `population_frequency`, `clinical_assertion`), `cohort_groups`, `dependency_groups`, integer `denominator`, `denominator_unit`, `controls: {positive, negative}` (each `passed`, `failed`, `unavailable`), `uncertainty`, `limitations`, `rationale`. Group lists are nonempty; write `unknown` rather than assuming independence. Denominator is nonnegative; observed/negative need >0, unavailable may use zero with its meaning explained. Denominator units distinguish retrieved records, assessed samples and chromosomes; do not interchange them. Explicit negative evidence needs an actual assessed record, its detection limit and rationale; no-record rows are always unavailable. Preserve excluded candidates, selection rationale, conflicts and sensitivity outputs as separate hashed artifacts.

Controls/threshold: retain failed/unavailable controls and shared samples/propagated summaries. Positive claims require all relevant controls passed. Failure: never merge incompatible genome builds; only an explicit valid reverse complement reconciles strand/allele differences. Failed controls downgrade affected claims instead of disappearing. No routine human gate; an interpretation-changing inclusion or dependency ambiguity is recorded and resolved before a replication assertion.

## 04-bound-claims

Accepted input: immutable ledger/table/snapshots and source limits. Calls the same synthesis and conditional domain skills; applies no new statistical estimator.

Output: `bounded-claims.json`, schema `variant-bounded-claims-v1`, nonempty `claims`. Each has unique `id`, exact `text`, `kind` (`descriptive`, `associational`), `basis` (`source_observation`, `association`, `population_frequency`, `clinical_assertion`), `status` (`supported`, `contradicted`, `inconclusive`, `unavailable`, `replicated`), distinct `evidence_sources`, `rationale`, `falsifier`, `uncertainty`, `applicability`. Basis must match each source's evidence type unless reporting only a descriptive source observation. Associational kind needs association rows. No available supporting record means unavailable. Population frequency cannot become clinical classification. A clinical assertion can only be reported descriptively, never adopted as a clinical conclusion. Failed controls or negative rows cannot support a positive claim. Replication also needs aligned biological context assessed independently; the validator checks declared group disjointness only.

Output: `dossier.json`, schema `variant-dossier-v1`, `stage_ids` exactly the ordered IDs, `identity_ledger`, `evidence_table`, `bounded_claims` each `{path, sha256}`, `review_status: unreviewed`, and `boundaries` exactly the five strings in `codex_science.variant_dossier.BOUNDARIES` (shown in the synthetic fixture). Extra fixture labels are descriptive metadata only. Paths stay inside the dossier, with no symlinks or parent traversal. Hash mismatch refuses handoff.

Run `python3 scripts/validate_variant_dossier.py <dossier-dir> --require-clean [--output <outside-dossier.json>]`. The module entry point is `validate_variant_dossier(Path)`. Output schema `variant-dossier-validation-v1` contains `schema`, `status: passed`, `review_status: unreviewed`, `source_count`, `claim_count`, `limitations`. Refusals are labelled ValueErrors; the CLI prints `variant-dossier-refused:` to stderr and exits 1 without traceback or overwriting an existing report. Invalid input exits 1 even without `--require-clean`.

Failure: correct stale links, reconcile from preserved source data or downgrade claims; never weaken controls. No routine human gate. No diagnosis, causality, clinical recommendation, clinical classification, or physical validity output is permitted; computational agreement and reviewer approval cannot establish those claims. Structured declarations are checked, while unregistered semantic overclaims in free text require independent source/method review.

## 05-review-handoff

Accepted input: passed validation, all immutable records/snapshots, existing manifest and separate claim-register paths/hashes, source dependencies, queries, exclusions, control outcomes, negative results, uncertainty and limitations. Calls `$science-provenance` for ordinary artifact registration and `$science-review` for independent record/source/method review; the coordinator alone chooses rigor and receipt handling.

Output: ordinary artifact packet delivered under the existing review contract; no new receipt schema and no self-issued review approval. The dossier remains `unreviewed` even when its mechanical validator passes. Review approval is never truth. Failed source or method checks return to affected stages with preserved prior records and new hash identities. No automatic publication or clinical use.

## Fixtures and acceptance

`examples/workflow-variant-evidence-dossier/synthetic-dossier/` is the positive normalized-only replay fixture; `expected-validation.json` freezes its report. `negative-cases.json`, schema `variant-dossier-negative-fixtures-v1`, specifies mutations by `id`, dossier-relative `target`, JSON `pointer`, replacement `value` and `expected_code`. The test loader rebinds unaffected hashes after semantic mutations; the hash-mismatch case intentionally retains its bad binding. Every case runs the public module and CLI, checking its named refusal. `benchmarks/workflow-variant-evidence-dossier/tasks.json` freezes questions, criteria and CPU/offline budgets in the pack-local `variant-dossier-benchmark-v1` schema. Quality L4 refers only to these deterministic software acceptance tests, never live-source or clinical validation.

## Concurrent calls and interrupted writes

The validator only reads inputs, so a second stable-input call returns the same report. Producers must keep snapshots and handoffs immutable; concurrent input replacement is outside its guarantee and requires revalidation. The optional report uses the shared atomic write helper: two calls leave one complete report (last replacement wins). Interruption before replacement preserves the old destination and may leave a same-directory temporary file on abrupt termination; interruption after replacement leaves the complete new report. No multi-file transaction, lock, review, or publication authority is implied. Fixture tests use isolated temporary directories and delete them after each run.
