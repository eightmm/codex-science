# Stages and pack-local record contracts

All examples are synthetic fixtures, redistributable under the repository license. No stage executes a source retrieval, install, remote job or external analysis tool. Register these domain records as ordinary artifacts; existing manifest, checkpoint, receipt and claim-register contracts remain unchanged.

## Invocation and identities

From the plugin root run:

```sh
python3 scripts/validate_bulk_expression_pack.py examples/workflow-bulk-expression-analysis/pack.json
python3 scripts/validate_bulk_expression_pack.py examples/workflow-bulk-expression-analysis/pack.json --output "$TMPDIR/bulk-expression-result.json"
```

The public Python entry point is `codex_science.bulk_expression_pack.validate_bulk_expression_pack(path)`. It returns the statistical result or a labelled `ValueError`. The thin CLI returns exit 2 with `error:` for refusals, without a traceback, and exit 0 for reference acceptance. `--output` must be outside the input bundle and cannot replace an input. With no output argument, only stdout is written. `--help` describes both arguments. No `--execute` option exists.

Paths in `inputs.expression` and `inputs.gene_sets` are bundle-relative, may not contain parent traversal, must resolve within the bundle and are SHA-256 checked before analysis. A path-plus-hash pair identifies each accepted input and every coordinator stage handoff. The coordinator records the pack path and hash before stage 1 and each new output path and hash before the next stage. Keep previous artifacts immutable; the runner does not write the input bundle. These identities detect changed bytes, not biological provenance or historical truth. The pack-local JSON loader preserves the repository's 64 MiB byte bound for each file and refuses duplicate keys at any nesting depth in packs, counts and collections with `invalid-record`. The absolute bundle root is pinned one directory at a time without following symlinks; each artifact is opened relative to that descriptor using nonblocking, no-follow opens. Directory/file identities and bounded bytes are checked across reads. Every root ancestor and all inputs are rechecked before success. Producers must finish writing immutable inputs before readers start.

Output writing uses the repository's atomic text writer. A second call to the same destination replaces it with one complete result; identical inputs produce identical JSON. Concurrent writers use separate temporary files and the last atomic replacement wins; use distinct run directories to preserve both runs. A kill before replacement leaves the previous complete destination (or no destination) and may leave a hidden temporary file beside it. A kill after replacement leaves the complete new result. No multi-file transaction exists because the runner writes at most one result; input files, checkpoints, refs and records are never mutated.

## Pack-local schemas

`bulk-expression-counts-v1` requires `schema`, `fixture: true`, `organism`, `genome_version`, `annotation_version`, `identifier_namespace`, `sample_ids` and `genes`. Sample and gene IDs are nonempty unique strings. Each gene row has `id` and one nonnegative integer `counts` entry for every sample, in the declared order. All input genes are tested, including all-zero rows. Empty gene or sample tables are refused. Detection is count greater than zero.

`bulk-expression-gene-sets-v1` requires the same identity fields and synthetic `fixture` label, plus `sets`. Each set has a unique nonempty `id` and a unique-string `genes` list, possibly empty. The collection must contain at least one set. Expression, collection and design identities must match exactly; no implicit mapping, deduplication or annotation repair occurs.

`bulk-expression-pack-v1` requires `schema`, `fixture: true`, `inputs`, `design`, `frozen_spec`, `frozen_sha256`, `analysis_spec`, `freeze_before_testing: true`, boolean `exploratory`, `removed_samples`, `stages` and `claims`. The input pairs have `path` and `sha256`. Design contains the four identity fields and `samples`, each with `id`, `condition`, `batch` and `covariates`. Samples are independent biological replicates by declaration; this cannot be verified from counts alone. The reference requires empty covariate objects and exactly the two retained contrast groups. A batch shared across conditions establishes that batch is not perfectly confounded; the reference still does not adjust batch effects.

Both specifications require `contrast` (two distinct groups), `model: "welch-log2-cpm"`, integer `minimum_replicates` at least 2, `alpha` and `enrichment_alpha` in [0,1], `correction: "BH"`, `correction_genes` (exactly all input genes), `enrichment_background` (unique IDs equal to all tested genes) and `qc`. QC requires nonnegative finite `min_library_size`, `min_detected_genes` and `max_log_library_deviation`. Zero thresholds are accepted; an actually zero library is refused. Threshold equality passes. Hash the frozen specification as UTF-8 JSON with sorted keys, compact comma/colon separators and no nonfinite numbers, using `specification_hash`. No statistic is computed until the hash, order declaration, current specification, QC and every refusal control passes. Any specification change requires `exploratory: true`; original and current hashes are both retained. A declaration and hash cannot prove when an external producer saw outcomes.

Each `removed_samples` entry requires `sample_id`, nonempty `reason` and `threshold` equal to the fixed maximum log-library deviation; the observed deviation must exceed that threshold. Unknown and duplicate removals are refused. Retained samples must pass every threshold. Removed samples and their failed control measurements remain in the result. Each claim has `id`, `text`, `kind` (`descriptive` or `associational`), `status` (planned/supported/suggestive/conflicting/unsupported/withdrawn/unavailable) and `evidence_basis` (`statistical` or `unavailable`). An unavailable basis requires unavailable status. Claims remain producer declarations, not review outcomes; independent review adjudicates support.

`bulk-expression-result-v1` contains `schema`, `fixture`, `evidence_level: "statistical-only"`, input identities, `frozen_sha256`, `analysis_sha256`, ordered `stages`, boolean `exploratory`, all `qc` rows, `differential`, `enrichment`, declared `claims`, `review: "unavailable"` and `limitations`. QC rows contain `sample_id`, `library_size`, `detected_genes`, absolute `log_library_deviation`, `excluded` and a removal record or null. Gene rows contain `gene_id`, `log2_fold_change`, `t`, `df`, `p_value`, `q_value`, `significant`. Set rows contain `set_id`, overlapping selected gene IDs, `members_in_background`, `p_value`, `q_value`, `significant`. The producer generates this schema after validation; no existing domain receipt or global record is extended.

## 01-design: fitness and design declaration

Accepted identities: supplied selection/context artifact path plus SHA-256 (coordinator), pack path plus SHA-256, and counts/collection pairs in the pack. Read the existing `public-omics-dataset-discovery` and `expression-cell-context` skills for selection, sample dependencies and expression interpretation; reuse their `omics-dataset-selection-v1` and `expression-context-evidence-v1` artifacts. The runner consumes only the admitted synthetic pack. Output: admitted `bulk-expression-pack-v1` with organism, tissue/assay scope in the coordinator contract, versioned identities and biological sample design. Controls: pseudoreplication, incomplete metadata, mismatched namespaces/versions and unsupported covariates. Failure: `unavailable`, `identifier-mismatch`, `unsupported-covariates` or `invalid-record`; retain rejected alternatives. Gate only for restricted transfers, new hosts or interpretation-changing identity choices.

## 02-qc: prespecified controls

Accepted identity: admitted pack path plus hash and its input pairs. Use the pack validator's QC. Library size is the sum of all counts for each sample; detection counts genes above zero. The outlier measurement is absolute log2(library size) minus median log2(library size) over all supplied samples. Output: the `qc` portion of `bulk-expression-result-v1`, retaining failed controls and recorded exclusions. Fix all three QC thresholds and minimum replicates before outcomes. Check batch overlap after exclusions; no overlap is perfect confounding. Stop with `qc-failed`, `outlier-removal`, `insufficient-replicates` or `batch-confounding`. No human gate for an admitted local QC run; material threshold changes are interpretation choices and require an exploratory revision.

## 03-freeze: contrast and model

Accepted identities: admitted pack and QC artifact paths plus hashes. The coordinator uses the existing manifest plan/one-checkpoint procedure; `references/plan.json` uses ordinary `id`, `description`, `status` steps. Save the pre-test specification and SHA-256 before stage 4. Output: unchanged `frozen_spec`, `frozen_sha256` and explicit timing declaration in `bulk-expression-pack-v1`. Controls include ordered stage IDs, original/current specification comparison and full-family correction. Fail with `freeze-hash`, `freeze-order`, `stage-order`, `post-result-change`, `multiple-testing` or `enrichment-background`. A timing declaration is not independent attestation. Preserve the original after changes. Gate only for interpretation-changing choices, never for routine hashing.

## 04-testing: differential association

Accepted identities: frozen pack and QC paths plus hashes. Call the reference CLI or public validator. Normalize counts to CPM over all supplied genes, add one, then log2. Use two-sided Welch with Satterthwaite degrees of freedom and Student-t probabilities computed via regularized incomplete beta; BH covers every tested gene. Report mean log-scale difference, second group minus first, p/q values and significance for testable genes with q <= alpha. If both groups have zero within-group variance, Welch is undefined regardless of their means. Retain each such gene, including all-zero genes, in BH with p=1 and null t/df; never select it, even at alpha=1. Record its gene ID and the zero-variance reason in the existing result `limitations` list. Output: `differential` in `bulk-expression-result-v1`. Preserve every nonsignificant result. On numerical failure stop with `numerical-failure`; no automatic method switching. DESeq2/edgeR style models need a separately authorized tool/environment and interpretation decision; the pack never installs or runs them. No human gate for the offline reference.

## 05-enrichment: supplied collection and explicit universe

Accepted identities: frozen specification, differential result and supplied collection paths plus hashes. Selected genes must be testable and have q <= alpha. Intersect each supplied set with the declared background; the background must equal the tested gene universe. Refuse both missing tested genes and extra untested genes, which could inflate significance despite never being selectable. Collection members outside that universe remain excluded by intersection. Use the upper-tail hypergeometric with population=background size, successes=set intersection size, draws=selected genes, observed overlap; BH covers all supplied sets. Zero selections or an empty set produce p=1 and remain visible. Output: every `enrichment` row in `bulk-expression-result-v1`. Stop on `enrichment-background` or `identifier-mismatch`. Interpretation must consider gene correlation, normalization and selection bias; enrichment never proves a causal pathway. No human gate unless the universe choice changes interpretation.

## 06-handoff: bounded claims and independent review

Only descriptive and associational claim kinds are allowed, for every status including `supported`. The conservative text filter rejects these words and their stem variants: cause/causal, mechanism, drive/drives/driven/driving, physical validity (space or hyphen), clinical, truth, therapeutic/therapy, efficacy, effective, treatment, induce, determine, regulate, activate, repress, responsible, biomarker, prognosis/prognostic and predict. The added therapeutic and outcome vocabulary follows the quality limitations against biological, causal, physical and clinical validation; biomarker and prediction wording cannot establish outcome validity from these synthetic associations. Matching is case-insensitive and includes negations, so it may refuse a cautiously worded statement too. It does not understand every unlisted paraphrase; independent review must still assess meaning and support.

Accepted identities: every input, frozen revision, QC record and result path plus SHA-256. Use `$science-provenance` for ordinary artifact registration and separate existing claim-register entries; use `$science-review` for independent record, source and method assessment. Output: `bulk-expression-result-v1` plus coordinator-owned existing provenance/claim/review artifacts. The pack does not write or certify review. Freeze claim requirements, uncertainty and falsifier in the decision contract; preserve supported, contradicted, inconclusive and unavailable dispositions, sample dependencies and all failed or negative controls. Refuse causal/mechanistic/clinical/physical-validity or truth claims with `claim-boundary`; unavailable evidence misrepresented as negative is `unavailable-evidence`. Reviewer approval is never truth. The smallest next action is an independent cohort or orthogonal assay capable of falsifying the association, with separately authorized compute or transfer if needed.
