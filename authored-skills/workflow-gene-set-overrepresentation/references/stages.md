# Gene-set stages and pack-local records

Every checked-in input, expected artifact and negative example is a synthetic fixture. This procedure adds no global schema, payload field, engine, checkpoint or review attestation.

## Invocation and immutable identities

Run `python3 scripts/validate_gene_set_overrepresentation_pack.py examples/workflow-gene-set-overrepresentation/pack.json`. The CLI accepts exactly one positional bundle argument and writes nothing. Success prints `gso-result-v1` JSON to stdout, exit 0. Refusal prints `{status: refused, error: labelled-reason}` JSON to stdout, exit 2, without a traceback. Argument errors use `cli-arguments`. `--help` describes the same read-only route; there is no output option.

Public Python entry points are `validate_gene_set_overrepresentation_pack(path)`, `reference_computation(rules, upstream, genes, collection)`, `hypergeometric_upper_tail(population, set_size, list_size, overlap)` and `benjamini_hochberg(values)` in `codex_science.gene_set_overrepresentation_pack`. They return admitted values or labelled ValueErrors. The pure computation validates the supplied record shapes and identities; filesystem hashes are checked by the bundle validator.

All handoffs are `{path, sha256}` with canonical bundle-relative POSIX paths and lowercase SHA-256. Refuse absolute paths, drive paths, backslashes, dot components, `..`, redundant separators and symlinked components. Hash the bytes actually parsed. Pin every root ancestor by walking directory descriptors with O_DIRECTORY, O_NONBLOCK and O_NOFOLLOW, comparing lstat/fstat device/inode at every step. Read artifacts relative to the pinned root descriptor with lstat, O_NONBLOCK, O_NOFOLLOW and fstat identity, regular-file and size checks. Refuse FIFOs, devices, directories, symlinks, oversized, growing and swapped inputs. Open each artifact once for admission; hardlink aliases share bytes and parsed JSON by device/inode. Reopen and hash each distinct inode at the end, verify every alias signature and reopen the root ancestry before and after final checks. Inputs may still change after the last check returns.

No runtime writer exists. Two concurrent calls write no file, ref, record, lock or receipt. A kill between reads leaves only the original immutable inputs; stdout may be incomplete. Fixture files and expected artifacts are checked-in identities, never regenerated by validation. The coordinator writes a new output artifact using existing provenance tools; it must not overwrite a previous reviewed identity. There is no multi-file transaction or stored-record migration, and no earlier writer exists for these new schema names.

JSON must be a UTF-8 object with unique keys at every depth and finite numbers of magnitude at most 1e100. Reject malformed roots, deep nesting, huge numbers, bool-as-number and wrong types with labelled errors. Every declared integer (`min_set_size`, `max_set_size`, `universe_size`, each `list_sizes` value, row `size` and `overlap`, and the four exact-tail arguments) must be an actual int, excluding floats, booleans and numeric strings. Schema names are versioned strings, with no integer schema-version field in runtime records.

Named limits, checked before the corresponding scaled work: `MAX_BYTES` 67108864 per artifact; `MAX_TOTAL_BYTES` 268435456 across distinct inodes; `MAX_TOTAL_NODES` 4000000 across admitted JSON snapshots; `MAX_ITEMS` 20000 entries per generic container; `MAX_DEPTH` 32 with root depth zero; `MAX_TEXT` 4096 characters; `MAX_GENES` 2000 per universe, upstream table, selected list or set; `MAX_SETS` 128; `MAX_LISTS` 2; `MAX_MEMBERSHIPS` 10000 before building collection intersections; `MAX_TESTS` 256 set/list pairs; `MAX_PAIRS` 32640 significant pairs before quadratic work; `MAX_TAIL_TERMS` 200000 across tested upper tails and per direct-tail call; `MAX_RECORDS` 128 artifact paths, evidence records or support references; `MAX_CLAIMS` 100; `MAX_NUMBER` 1e100. JSON admission preflights the remaining value allowance with `1 + commas + nonempty-container starts` using a non-consuming lookahead. This conservative upper bound may overcount punctuation inside strings. It is charged once per inode before parsing. Byte budgets use fstat sizes before reading; reads are bounded by admitted size plus one growth-detection byte. Equality at limits passes when other controls hold.

## Pack-local schemas

Objects reject missing and unknown fields. Every record has `schema` and `fixture: synthetic fixture`; claims below are local fields, never replacements for existing claim-register records. Example objects are in the synthetic bundle.

| Schema | Other required fields |
| --- | --- |
| `gso-pack-v1` | `stages` equal plan IDs; `frozen_rules_sha256`; identities `rules`, `report`; `evidence` identity list; `claims` list. |
| `gso-rules-v1` | `namespace`, `organism`, nonempty `selection_rule`; boolean `selected_before_sets`, `exploratory`, `directional`; integer `min_set_size`, `max_set_size` in [1,MAX_GENES] with min<=max; `alpha`, `overlap_limit` in [0,1]; `collection_version`; identities `upstream`, `genes`, `collection`. |
| `gso-upstream-v1` | `namespace`, `organism`, nonempty `rows`, each exactly `{gene, selected, direction}`. Unique gene text, boolean selected, direction up/down/none. Every row is an upstream tested gene, including unselected rows. |
| `gso-list-v1` | `namespace`, `organism`, nonempty unique `universe`; nonempty `lists`, each `{direction, genes}` with nonempty unique genes. Universe equals the upstream tested rows exactly. List union equals upstream selected flags exactly, with no cross-list duplicates. |
| `gso-collection-v1` | `namespace`, `organism`, `version`, nonempty `sets`, each `{id, genes}`. Set IDs are unique alphanumeric/underscore/hyphen strings; members unique but may be empty or outside the tested universe. |
| `gso-report-v1` | `rules_sha256`; frozen `namespace`, `organism`, `collection_version`; integer `universe_size` and `list_sizes` mapping each admitted direction to its integer denominator; `rows`, `jaccard`, `findings`, `correction: BH-all-tested-sets`, boolean `exploratory`, matching the complete reference result. |
| `gso-evidence-v1` | Nonempty `records`, each `{id, kind, result, origin, source}`; unique text IDs, kind/result text, origin study/external/independent/preregistered, and source identity resolving as a JSON object. |
| `gso-result-v1` | `stages`, `status: statistical-overrepresentation-only`, `review: unavailable`, `rules_sha256`, `computation`, `claims`, `input_identities` including the entry pack and every admitted alias. |
| `gso-negative-fixtures-v1` | `cases`, each `{id, code, changes}`; each change `{target, path, value}` edits an explicitly named synthetic object. The acceptance tests apply these and refresh dependent hashes before checking the named refusal. This test-only recipe is not executed by the validator. |

Namespace is `gene_symbol` (letter then up to 63 letters/digits/underscore/dot/hyphen, excluding Ensembl-shaped IDs) or `ensembl_gene_id` (ENS, optional species letters, G, digits, optional numeric version). All metadata must agree with the freeze. Identifier syntax and supplied organism metadata cannot establish true organism identity; source review must check it.

Computed rows are exactly `{id, size, overlap, tested, p_value, q_value, status}` in list/collection order. IDs join direction and set ID with a colon. `size` is after intersection; `overlap` is with the current list. Status is untested/non-significant/significant. Untested rows have tested false and null p/q. Jaccard rows are `{first, second, jaccard}` for every pair of significant rows. Findings are ordered components containing sorted row IDs, including singleton components. Memberships and indices are cached outside numerical loops.

Local claims are exactly `{id, kind, text, status, evidence}`. Kind is descriptive/associational. Status uses planned/supported/replicated/suggestive/conflicting/unsupported/withdrawn/unavailable; validate strings before membership or dictionary access. Evidence is a unique list of known record IDs. Empty evidence forces unavailable; any cited unavailable kind or result forces unavailable for every other status, including mixed evidence. Unavailable text cannot assert supported, replicated, suggestive or significant. Replicated is always refused in this single-study synthetic reference. External/independent/preregistered source identities must differ from every own input/output path and hash; copying or hardlinking cannot manufacture independence. Independent review remains a separate coordinator-owned action.

## 01-freeze: rules before the collection

Inputs: entry pack and rules path-plus-hash. Calls: existing `$cx-statistical-decision-analysis` framing and the local validator's rule gate. Output: admitted `gso-pack-v1`/`gso-rules-v1` identities. Check `frozen_rules_sha256` before opening upstream, list or collection. Fix namespace/organism, selected flags and rule, directional separation, size bounds, BH alpha/family and redundancy limit. Collection version/hash are in this freeze. A declared post-set selection must be exploratory; preserve that label in the report. Stop on rule-freeze or post-selection; retain failed revisions. Hashes prove byte identity, not historical selection time. Human decision only for an interpretation-changing choice or missing essential source.

## 02-identity: upstream tested universe

Inputs: frozen upstream/list/collection identities. Calls: local identity checks, with `$cx-public-omics-dataset-discovery` for upstream source fitness when used by the coordinator. Output: admitted `gso-upstream-v1`, `gso-list-v1`, `gso-collection-v1`. Refuse tested-universe, outside-universe, identifier-namespace, duplicate-list, selection-rule and direction-lists defects before inspecting claimed results. Combined lists are allowed only for a nondirectional freeze. A directional freeze requires ordered up and down nonempty lists matching upstream signs. Empty selected lists and lists equal to the whole tested universe are degenerate refusals. Preserve null/failed upstream controls in the coordinator packet; do not silently repair them. No new local permission gate.

## 03-testing: exact upper tails and complete-family FDR

Inputs: unchanged identities and inclusive size bounds. Calls: local `hypergeometric_upper_tail`, `benjamini_hochberg` and validator CLI. Output: `gso-report-v1` rows, verified as part of `gso-result-v1`. For universe N, set K, list n and observed overlap k, compute sum from x=k through min(K,n) of C(K,x) C(N-K,n-x), divided by C(N,n). Use math.comb and fractions.Fraction, converting once at the end. Refuse impossible counts, zero-sized sets, empty or whole-universe lists in direct numerical calls. Zero overlap is valid but cannot be enriched, even at alpha=1. No floating sign products or approximate tail libraries are used.

BH sorts all tested p-values across all lists, sets each adjusted value to the minimum of later m*p/rank and one, then restores original order. No significance-selected family. All sets outside the bounds remain present as untested with null p/q. Failure codes include set-size-bounds, empty-overlap, multiple-testing, tested-family and reference-computation. Preserve nulls and negatives, never retry by changing the family. No local permission gate.

Synthetic hand checks: N=30,n=6,C(30,6)=593775. Planted K=5,k=5 has p=25/593775. Redundant K=6,k=6 has p=1/593775. Raw-only K=5,k=3 has p=(10*2300+5*300+25)/593775=24525/593775; its BH q with four tested sets exceeds alpha=.05 although raw p does not. Empty-overlap p=1; size-one set is untested. These are software acceptance criteria, not real enrichment evidence.

## 04-redundancy: one finding per connected component

Inputs: same collection identities and all significant rows. Calls: reference pairwise Jaccard and connected components. Output: report `jaccard` and `findings`. Jaccard is intersection/union of universe-intersected set members, for all significant pairs including different directions. Link only when Jaccard is strictly greater than the frozen limit; equality does not link. Transitive components each count once, never as independent confirmations. The planted/redundant synthetic Jaccard is 5/6; at limit .8 they form one finding. Refuse redundant-findings on changed pairs or split components. No local permission gate.

## 05-handoff: bounded claims and independent review

Inputs: complete unchanged domain records, ordinary provenance artifacts, claim-register entries, failed controls, negative results, untested sets and limitations. Calls: `$science-provenance`, then coordinator-owned `$science-review` in record/source/method modes. Output: `gso-result-v1` plus a separate review packet, never a producer approval. The coordinator selects rigor and owns the single checkpoint and receipt registration. Review stays unavailable here.

The conservative case-insensitive English gate uses whole-word prefix families with `\w*`: caus*, mechanis*, therap*, clinic*, efficac*, effective*, treat*, cure*, prevent*, recommend*, prescri*, bind*, affinit*, inhibit*, activat*, regulat*, drive/drives/driv*, induc*. It additionally refuses truth, physical validity (spaces or hyphens) and patient benefit. It applies to all claim statuses and includes negations. It is incomplete for unlisted paraphrases; independent review must assess meaning. Every positive status (supported, replicated, suggestive) checks both cited kind and result for review/approval/computed/numerical/agreement/truth/physical/clinical labels. Claim labels cannot bypass it. Association is never causality, computed agreement never physical or clinical validity, absent evidence is unavailable, and approval never truth.

Human gates only before installation, restricted transfers, new hosts, GPU/remote/heavy compute or interpretation-changing choices. This offline CPU-only reference requests none of those actions. A failed control remains visible in the coordinator record; fix the specific input before another bounded attempt.
