# Particle-size stages and local record contract

Every checked-in table, question, refusal and expected artifact is a synthetic fixture. This contract checks arithmetic, not observations, product properties or independent review.

## Invocation and immutable identities

Public entry points: validate_particle_size_distribution_pack(bundle) and compute_particle_size_distribution(table, rules, bin_edges_um=None) in codex_science.particle_size_distribution_pack. The computation accepts parsed pack-local objects; file admission uses the validator. Invoke:

```bash
python3 scripts/validate_particle_size_distribution_pack.py examples/workflow-particle-size-distribution/pack.json
```

One bundle argument; no output option. Acceptance prints psd-result-v1 JSON on stdout, exit 0. Every refusal, including missing, extra and unknown arguments, prints JSON with status refused and finding on stderr, exit 2. Help prints plain usage on stdout, exit 0. Every refusal is a labelled ValueError, never an automatic input repair.

The validator writes no files, refs or records. Concurrent calls independently read identical bytes. A kill leaves all input files unchanged and may truncate stdout. The coordinator captures durable output atomically; a partial stdout stream is not a result. Every supplied JSON artifact is immutable for the entire call.

Artifact identities are exactly path and sha256: a canonical relative POSIX path inside the bundle and lowercase 64-hex SHA-256 of the bytes parsed. The entry-point pack has no initial declared hash. Refuse absolute paths, traversal, backslashes, symlink components, special files, noncanonical names and missing paths. Pin the root by walking every absolute ancestor with directory descriptors, O_DIRECTORY, O_NOFOLLOW and O_NONBLOCK; compare lstat/fstat device and inode at every open. Retain the root descriptor and every ancestor identity. Open artifacts relative to pinned descriptors, lstat regular files, open O_NONBLOCK/O_NOFOLLOW, fstat identity/size, bounded read and post-read signature. Hash exactly the parsed bytes. Hardlink aliases share initial bytes and parsing by device/inode. Re-read each distinct inode once at the end, verify all aliases and hashes, and compare the entire ancestor chain before and after. Root, parent or artifact swaps are refusals.

## Limits and types

Named constants: MAX_BYTES 67108864 per file; MAX_TOTAL_BYTES 268435456 aggregate distinct initial bytes; MAX_NODES 4000000 total JSON values; MAX_ROWS 10000 measurements and generic container entries; MAX_SAMPLES 128 samples; MAX_BINS 2048 bins (2049 edges); MAX_RECORDS 128 evidence documents, total evidence records, claims and citations per claim; MAX_STRING 4096 characters; MAX_DEPTH 32; MAX_NUMBER 1e100 generic absolute numeric magnitude; MAX_COUNT 1000000000000 in-range particles per measurement. Nonzero edges are at least MIN_EDGE 1e-12 micrometres; all edges are at most MAX_EDGE 1e12. Zero is allowed as the bottom edge.

Check bounds before proportional work, set building or computation. Equal collection and byte budgets pass; excess refuses. The preparse JSON upper allowance counts one root, commas and nonempty containers using an iterator with non-consuming lookahead; quoted punctuation can conservatively overcount. Do not allocate a match list. Enforce the remaining bundle allowance before json.loads. Hardlinks consume byte and JSON allowances only once. JSON refuses duplicate nested keys, non-object roots, malformed UTF-8, NaN/Infinity, huge numbers, excessive nesting and invalid types. Every declared integer is a real int, never bool, float or numeric string. All numerical inputs are finite. Missingness is explicit.

## Pack-local schemas

All six schemas are ordinary artifacts, not extensions to existing schemas or receipts. Every input has schema equal to the name below and fixture equal to synthetic fixture. Object fields are exact; unknown or missing fields refuse.

- psd-pack-v1: rules, table, report artifact identities; evidence list of identities; frozen_rules_sha256 equal to rules.sha256; real boolean frozen_before_table_read true. Validate the hash declaration before opening the table. This does not prove historical ordering.
- psd-rules-v1: unique nonempty sample_ids; nonempty measurements with exactly measurement_id and sample_id; bin_edges_um; basis count or volume; interpolation_rule linear-cumulative-within-bin; reported_statistics exactly D10_um, D50_um, D90_um, span, mean_by_number_um, volume_weighted_mean_um in that order; mean_rule bin-midpoints-spherical-volume; integer minimum_total_count from 1 through MAX_COUNT; integer minimum_replicates from 2 through MAX_ROWS; d50_relative_range_max and span_relative_range_max finite from 0 through 10; tail_fraction_max finite from 0 through 0.1; tail_rule exclude-at-or-above-limit. Measurement IDs are unique and each sample_id belongs to the unique sample list. Replicate identities and the minimum are fixed before data.
- psd-table-v1: bin_edges_um matching frozen edges exactly; nonempty rows. Each row is exactly measurement_id, sample_id, basis, values, total_count, below_range_fraction, above_range_fraction, availability. Every frozen measurement appears once with matching sample and basis. Availability is observed or unavailable. Unavailable requires null values, total_count and both tails. Observed values have one value per bin: nonnegative integer counts or nonnegative volume fractions. Count sum equals integer total_count; volume fractions sum to one within absolute normalization tolerance 1e-9. total_count is a real integer from zero through MAX_COUNT, describing counted in-range particles; for volume tables it is independently supplied measurement metadata. Both tail fractions describe the whole distribution on the frozen basis, each from zero to one and combined at most one. Tail fractions are required even when zero; they are not inferred from counts.
- psd-report-v1: rules_sha256; real boolean exploratory; applied bin_edges_um; basis; interpolation_rule; tail_rule; ordered measurements and samples; summary; nonempty headline; claims. Applied edges may merge adjacent original bins only, retaining both outer edges; any change requires exploratory true. Original rules, original table and hashes are retained. Recompute all quantities for the merged bins. Basis, interpolation and tail policy remain frozen. Wording and evidence gates precede table arithmetic.
- psd-evidence-v1: records list. Each record is exactly id, kind, result, origin and source artifact identity. IDs are unique across evidence documents. Kind and result are nonempty text; origin is internal, external, independent or preregistered. Every source is opened and hash-checked. Non-internal source path and hash must differ from every pack, rule, table, report and evidence-document identity. Hardlinks and content copies cannot create independence. Non-aliasing does not establish real-world independence.
- psd-result-v1: validator-produced schema, fixture, status arithmetic-only, review unavailable, ordered stages, exploratory, input path/hash identities, computation, claims and limitations. Computation contains measurements, samples and summary. It is never a passed review receipt. expected.json contains a synthetic fixture label, hand derivation and computation. negative-cases.json contains a synthetic fixture label and independent mutations with id, finding, changes; each change supplies target document, path and value.

Each computation measurement is exactly measurement_id, sample_id, classification (reliable, unreliable or unavailable), reasons list and statistics (the six named quantities or unavailable). Unavailable reasons are unavailable-record; unreliable reasons are count-rule and/or tail-rule in that order. A reliable reason list is empty. Each sample is exactly sample_id, classification (summarized or unavailable), included_measurement_ids, excluded_measurement_ids, relative_ranges (d50 and span, or unavailable) and statistics (six means, or unavailable). Summary is exactly integer n, summarized, unavailable, reliable_measurements, unreliable_measurements and unavailable_measurements. n counts samples, never measurements. Reported values match with relative tolerance 1e-9 and zero absolute tolerance, including near-zero comparisons. Normalization of volume fractions is the separate absolute 1e-9 requirement.

## 01-rule-freeze

Input: coordinator decision contract, question, claim IDs, identities and assumptions. Call $cx-statistical-decision-analysis for framing and $science-provenance for immutable rules.json plus SHA-256 (psd-rules-v1). Output: frozen identity, existing manifest plan and one coordinator checkpoint. Freeze edges/units, basis, interpolation, all six quantities, means convention, count minimum, replicate identities/minimum, agreement bounds and tail rule. Stop for essential missing choices. A later interpretation-changing choice requires a human gate; exploratory labelling never erases original rules.

## 02-table-qc

Input: frozen rules path/hash and table.json path/hash. Call the validator's identity and table checks. Output: admitted psd-table-v1 ordinary artifact with preserved availability and QC reasons in psd-result-v1. Count/fraction/edge/type/identity defects refuse. Total count at or below the minimum is unreliable; combined lower-plus-upper tail fraction at or above the limit is unreliable. Equality therefore fails these two strict rules. A zero tail limit excludes every observation. Unreliable measurements have unavailable quantities and never enter sample means. An absent record requires an explicit unavailable row, never a negative finding or zero. Retain raw failures and negative results.

## 03-distribution

Input: admitted immutable rules/table identities and applied edge declaration. Call compute_particle_size_distribution through the CLI. Output: per-measurement psd-report-v1 and psd-result-v1 quantities. Merge values by adjacent original bins if explicitly exploratory. Normalize in-range bin masses to sum one. Let L and U be recorded lower/upper tail fractions; whole-distribution bin mass is (1-L-U) times the normalized in-range mass. Start the cumulative curve at L. For each percentile q in 0.1, 0.5 and 0.9, find the first nonzero bin reaching q, and return left edge plus bin width times (q minus previous cumulative mass) divided by bin mass. Zero-mass bins are skipped. The tail limit at most 0.1, strictly enforced, keeps these percentiles inside the measured range. No percentile is interpolated on bin heights or a non-cumulative curve.

Span is (D90-D10)/D50. Require positive median and positive spread; refuse degenerate arithmetic. Means apply to in-range bins only. With midpoint d, count basis uses number weights n and volume weights n times d cubed; volume basis uses volume weights v and number weights v divided by d cubed. Normalize each weight family and take its weighted mean of d. Diameter cubing is scaled by the largest midpoint to avoid unnecessary overflow/underflow. This spherical-volume assumption and midpoint approximation are not observations; bin widths and nonspherical particles need separate sensitivity and method review. No zero-variance significance test is produced; identical technical replicates are permitted.

For each sample use all reliable replicates, never a favorable subset. With at least minimum_replicates, compute relative range (max-minus-min)/arithmetic mean separately for D50 and span. Both relative ranges must be at or below their frozen bounds; equality passes and zero allows identical values only. Average each of the six quantities over the agreeing replicates; do not pool bin counts. Too few reliable replicates or either failed agreement yields unavailable summary and no included IDs. Retain measured quantities, exclusions and failed agreement ranges. Technical replicates are not independent samples.

## 04-summary

Input: every computed measurement and sample plus original identities. Call reference/report comparison. Output: psd-report-v1 quantities and integer denominators, all exclusions and unavailable summaries, plus uncertainty, applicability, conflicts, dependencies, failed controls and negative results. Never give unreliable measurements numerical summaries or pool disagreeing replicates. No estimate of product quality, stability or performance follows from successful arithmetic.

## 05-handoff and claim gate

Input: report and evidence path/hash identities, rules, tables, failed revisions and coordinator records. Call $science-provenance for ordinary artifacts and separate existing claim-register entries, then $science-review for independent record/source/method review. Output: unreviewed psd-result-v1 and coordinator-owned checkpoint/claim register; only the coordinator registers later review receipts and rigor. Every failure remains in immutable inputs and caller-captured refusal JSON.

Claims are exactly id, kind, status, text and evidence IDs. Kind is descriptive or associational. Status is planned, supported, replicated, suggestive, conflicting, unsupported, withdrawn or unavailable. No evidence requires unavailable. Any cited unavailable kind or result requires unavailable for every other status, including mixed evidence. Unavailable claims cannot assert supported, replicated, suggestive or significant evidence. Replicated is always refused: this synthetic fixture cannot establish independent studies. Positive statuses supported, replicated and suggestive cannot cite any record whose kind OR result denotes review, approval, computation, numerical agreement, truth, physical or clinical validity.

The conservative case-insensitive English whole-word/prefix wording families are: caus*, mechanis*, therap*, clinic*, efficac*, effective*, treat*, cure*, prevent*, recommend*, prescri*, bind*, affinit*, inhibit*, activat*, regulat*, drive/drives/driv*, induc*. Also refuse truth, physical validity, patient benefit, quality, stabil*, stabl*, perform*, approv*, certif*, compliance and compliant. This lexical check includes negations and is incomplete for unlisted paraphrases and other languages. Claim kind never bypasses it. Association is never causality; computation is never physical or clinical validity; missing evidence is unavailable, never negative; review approval is never truth.

Human gates apply only before installation, restricted transfers, new hosts, GPU/remote/heavy compute or interpretation-changing choices. No network, install or remote behavior exists in this pack. No gate at every admitted offline stage.
