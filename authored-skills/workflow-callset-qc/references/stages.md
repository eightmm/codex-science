# Synthetic callset stages and local records

All checked-in examples are synthetic fixtures. The reference is a tab-free JSON table, not a VCF reader. Only unphased diploid biallelic SNP calls on chromosomes 1 through 22 and X are accepted. There is no haploid, PAR, indel, structural-variant, multiallelic decomposition or strand normalization model. X is a declared diploid heterozygosity proxy, never an inference of sex identity.

## Entry points and identities

Run `python3 scripts/validate_callset_qc_pack.py examples/workflow-callset-qc/pack.json` from the repository root. It takes exactly one bundle JSON argument and writes nothing. Successful JSON goes to stdout with exit zero. Every refusal is a labelled ValueError rendered as JSON containing status refused and finding on stderr with exit two; no traceback. Missing, extra and unknown arguments use invalid-arguments. Help is plain usage on stdout with exit zero. There is no output option.

Python entry points are `validate_callset_qc_pack(path)`, `compute_callset_qc(table, rules)` and `hardy_weinberg_exact(hom_ref, het, hom_alt, minimum=2)` in `src/codex_science/callset_qc_pack.py`. The last two accept already-parsed synthetic objects and return deterministic arithmetic; only the validator admits on-disk identities and claims.

An identity is exactly path and sha256. Paths must be canonical, bundle-relative POSIX paths: no absolute or drive paths, parent traversal, backslashes, empty components, dot components or symlinked components. SHA-256 is the lowercase digest of the exact bytes parsed, not serialized JSON. Source labels never prove independence; external, independent and preregistered support is refused if its path or hash, or its declared source path or hash, equals one of this study's inputs, frozen rules or pack.

The root is pinned by walking each absolute directory component with descriptor-relative, non-following opens. Every ancestor device/inode is retained and compared before and after final hash verification. Each artifact receives lstat, nonblocking non-following open and descriptor fstat checks, a bounded read, and a final hash recheck. Hardlink aliases share one parse and initial read per device/inode; final verification hashes each distinct inode once and checks each alias. Replacing or growing inputs is refused. Concurrent validators write nothing; terminating either leaves only the caller's original bundle. The producer must publish a complete new bundle before validation; a kill between producer writes causes an input-hash refusal, never acceptance of a partial handoff.

## Resource limits

All bounds are module constants and apply before work scaling with each dimension. MAX_BYTES is 64 MiB per file; MAX_TOTAL_BYTES is 256 MiB of unique initial input bytes. MAX_TOTAL_NODES is 4,000,000 bundle-wide parsed JSON values, with a conservative upper-bound check before each parse. The upper bound counts one root, commas, and nonempty containers without allocating a match list. MAX_RECORDS is 1,000 artifact paths. MAX_ITEMS is 20,000 entries in any JSON container; MAX_DEPTH is 64; MAX_TEXT is 8,192 characters per key or string; MAX_NUMBER is the finite magnitude bound of ten to the power one hundred. Raw literal tab characters are invalid JSON inside strings; escaped tabs have no field-separator semantics.

MAX_SAMPLES is 256, MAX_SITES is 10,000, MAX_CELLS is 1,000,000 site-by-sample cells, MAX_TRIOS is 256, MAX_CLAIMS is 1,000 and MAX_SUPPORT is 100 citations per claim. Zero sites and zero samples are refused. Empty trios, empty claims and empty unavailable support are permitted. Exact Hardy-Weinberg enumeration uses at most MAX_SAMPLES controls; its minimum must be at least two. Counts, positions, minimum counts and every schema_version are real integers: bools, floats and numeric strings are refused. All versions are exactly one. Other numerical fields accept finite integers or floats, never bools. Duplicate JSON keys, non-object roots, malformed or deeply nested JSON, non-finite and huge numbers are refused.

## 01-freeze

Accepted input: `pack.json` under callset-qc-pack-v1 and its freeze.rules identity under callset-qc-rules-v1. Rules are loaded and validated before the table identity is opened. Called tools: this pack validator and coordinator-owned `$science-provenance`. Output: immutable original `rules.json` identity, or a preserved original plus revised rules identity; ordinary artifact, not a new global schema.

The pack fields are schema, schema_version, fixture, stages, mode, freeze, inputs and claims. Stages are exactly 01-freeze, 02-table-qc, 03-metrics, 04-summary, 05-handoff. Mode is frozen or exploratory. Inputs names rules, table and qc each hold identities. Freeze holds rules, before_genotypes, frozen_at and genotypes_read_at. Before_genotypes must be true; timezone-aware frozen_at must precede genotypes_read_at. Unequal original and applied rule hashes require exploratory. These declarations cannot prove historical timing or prevent a dishonest producer from inventing a freeze.

Rules fields: schema, schema_version, fixture, genome_build, samples, trios, site_filters, sample_filters, titv_range, allele_balance, strand_ambiguous, multiallelic and sex_check. Each sample has id, sex, control and family. Sex is female, male or unknown; control is boolean; family is a nonempty explicit declaration, with unrelated used for no declared family. A trio has id, father, mother and child; three distinct sheet IDs share a family other than unrelated. Reused sample and trio IDs are refused.

Site_filters contains minimum_quality, minimum_depth, maximum_missingness, hwe_p_cutoff, hwe_scope and minimum_controls. Hwe_scope is controls-only. Minimum_controls is two through MAX_SAMPLES. Missingness and p cutoffs are in the closed unit interval; quality and depth are nonnegative. Sample_filters has minimum_call_rate in the unit interval and the mandatory inclusive heterozygosity_range. Titv_range and allele_balance are ordered inclusive endpoint pairs; Ti/Tv endpoints are nonnegative, allele balance endpoints are in the unit interval. Strand_ambiguous is retain-labelled or exclude; multiallelic is refuse. Sex_check has enabled, female_minimum, male_maximum and minimum_sites. Thresholds are in the unit interval, male_maximum is below female_minimum, and minimum_sites is a positive integer.

Controls and thresholds are immutable before outcomes. Failure handling: rule-freeze, post-outcome-filters, unfrozen-heterozygosity, hwe-controls-only, allele-handling or invalid-record; preserve original and failed revision. Human decision gate only for a material interpretation-changing rule choice, outside this fixed synthetic fixture.

## 02-table-qc

Accepted input: inputs.table path and hash under callset-qc-table-v1, with the same frozen genome_build and exact sample order. Called tool: compute_callset_qc. Output: admitted table identity and explicit identity findings.

Table fields: schema, schema_version, fixture, genome_build, samples and sites. Samples is the exact ordered sheet ID list. Each site has id, chrom, position, ref, alt, quality and calls. Sites have unique IDs and strictly increasing chromosome/position pairs in numeric autosome order then X. Position is a positive integer no greater than the signed 32-bit maximum. Ref and alt are different uppercase A, C, G or T bases. Each calls list is exactly one entry per sample; each entry has gt, depth, quality and alt_depth. Genotypes are exactly 0/0, 0/1, 1/1 and `./.`. Depth, quality and alt_depth are finite and nonnegative; alt_depth cannot exceed depth. Call quality is retained but no independent genotype-quality threshold is applied; the frozen minimum_quality is site quality. Do not silently invent a genotype-quality filter.

Failure handling: input-file, input-root, input-path, input-hash, input-changed, input-limit, invalid-json, invalid-record, build-mismatch, sample-identity, site-identity, trio-identity, allele-handling or genotype-vocabulary. No repair, external source or human gate is needed for a valid synthetic fixture.

## 03-metrics

Accepted input: admitted table and applied rules identities; outputs `qc.json` under callset-qc-report-v1 and a recomputed comparison. Called tools: compute_callset_qc and hardy_weinberg_exact. No network or third-party dependency.

A single site-filter pass uses all original samples, including samples later removed. A site is removed for minimum-quality if site quality is below the frozen minimum, minimum-depth if any observed call is below its minimum, maximum-missingness if the fraction of missing calls exceeds its maximum, allele-balance if any heterozygote has zero depth or alternate/total depth outside its inclusive interval, strand-ambiguous when A/T or C/G is excluded by declaration, or hwe-controls if the exact p value is strictly below cutoff. The missing genotype token is `./.`. No missing call is reference. Each reason is preserved; equality to a threshold passes.

For each autosomal site, Hardy-Weinberg uses only nonmissing calls in declared controls. It conditions on the minor-allele count and enumerates possible heterozygote counts of the same parity. Table weights are proportional to two raised to heterozygote count, divided by the three genotype-count factorials. The two-sided p value sums weights no greater than the observed weight, with a tiny log-weight tie tolerance. math.fsum and log-gamma stabilize enumeration. No asymptotic approximation or mid-p value is used. Monomorphic, insufficient controls or non-autosomal sites remain unavailable with an explicit reason and never become p value zero. There is no automatic site exclusion on an unavailable HWE test and no implicit multiplicity claim.

Sample metrics use retained sites exactly once, without a second site pass after sample removal. Call rate is observed calls divided by retained sites; heterozygosity is heterozygotes divided by observed calls. All missing gives zero call rate and unavailable heterozygosity. Sample reasons are minimum-call-rate, heterozygosity-range or heterozygosity-unavailable. Per-sample Ti/Tv counts nonreference sites once, not alternate allele copies. Overall Ti/Tv counts retained sites, including X. A/G and C/T in either direction are transitions; all other valid substitutions are transversions. Zero transversions yields unavailable, never a significant-looking number; an out-of-range overall ratio is a failed control, not an invented filter.

Trio checks use every original autosomal site, even excluded sites or samples. A missing member yields an unavailable site; otherwise a child's unordered alleles must be constructible from one paternal and one maternal allele. Report every error and its count. X is excluded from Mendelian arithmetic. The sex check uses every original observed X call, even excluded sites or samples. At minimum_sites, declared males must be at or below male_maximum and declared females at or above female_minimum; unknown, disabled or insufficient observations stay unavailable. A contradiction is a failed control and never silently dropped.

Report fields: schema, schema_version, fixture, hwe_scope, missing_rule, sites, samples, removed_sites, removed_samples, mendelian, sex_checks, titv, failed_controls, retained_sites and retained_samples. Each site metric is id, missingness and hwe; hwe has status, p_value, reason and controls_called. Each sample metric is id, called, heterozygous, call_rate, heterozygosity and titv. Ti/Tv objects have transitions, transversions, value and status. Removal rows have id and nonempty reasons. Trio rows have id, errors, error_count, informative and unavailable_sites. Sex rows have id, x_called, x_heterozygosity and status. Counts must have integer types and match recomputation. Missing_rule is unavailable; hwe_scope is controls-only. Report equality uses strict record types and a tolerance only for real-valued arithmetic.

Failure handling: empty-retained-sites refuses an undefined sample denominator. The public exact-test helper refuses hwe-unavailable for too few, excessive or monomorphic controls; the cohort computation preserves only this named data failure as unavailable. Other errors propagate. Unnamed-site-filter, site-filter-mismatch, hwe-controls-only, unavailable-as-reference, mendelian-ignored, sex-contradiction-ignored and qc-report-mismatch retain distinct refusal order. No interpretation gate occurs during arithmetic.

## 04-summary

Accepted inputs: inputs.qc identity and recomputation, with the original rules and table identities. Output: callset-qc-result-v1 JSON on stdout. Fields are schema, schema_version, fixture, status, review, evidence_boundary, mode, stages, qc and inputs. Status is checked, review is unavailable, and evidence_boundary is synthetic-arithmetic-only. Inputs lists every admitted path and SHA-256. It writes no file. A caller saving it should use an atomic new artifact and register its final hash separately.

The synthetic fixture has six samples and seven sites. Retained sites are fixture-site-1, fixture-site-2 and fixture-site-7. Four sites fail quality, depth, allele balance and missingness respectively; bad-sample has zero call rate and unavailable heterozygosity. At the first site, the four controls have one reference homozygote, two heterozygotes and one alternate homozygote, giving exact p value one. Overall Ti/Tv is one half. Father has one third heterozygosity, a contradiction on X and the declared trio has an error at fixture-site-2. Fixture-site-6 is unavailable for trio comparison. Failed controls remain visible and do not become a passing scientific conclusion.

## 05-handoff and claim gate

Accepted inputs: original and applied rules, table, report, all evidence sources and separate claim-register entries with immutable paths and hashes. Called skills: `$science-provenance` and coordinator-owned `$science-review`. One checkpoint per run; no schema change, receipt generation or review self-attestation.

Pack-local claims contain exactly id, kind, status, text and support. These are a local gate only; the coordinator maps them to the existing separate claim-register contract. Kind is descriptive, associational, causal or confirmatory, but causal is always refused. Status is planned, supported, replicated, suggestive, conflicting, unsupported, withdrawn or unavailable. Every key used for identity is checked as text first. No evidence requires unavailable status. Any unavailable cited kind or result, in either the evidence or its source, requires unavailable status even with mixed observed evidence. Unavailable text cannot say supported, replicated, suggestive or any word starting significan. Replicated is always refused for this single synthetic fixture.

Each support object has origin, path and sha256. Origin is study, external, independent or preregistered. The hashed record is callset-qc-evidence-v1 with schema, schema_version, fixture, id, kind, result and source. Kind and result are nonempty text checked separately. Source is an identity resolving to a JSON object; any declared schema, kind or result must be text and any declared schema_version must be integer one. A source under callset-qc-report-v1 or callset-qc-result-v1 is always computed, regardless of wrapper labels. Positive claims cannot cite kind or result containing review, approv, comput, numer, physical, clinic or truth in the evidence or source. Merely labelling a source independent never changes these checks.

Every claim text has a conservative case-insensitive whole-word English lexical gate. Prefix families consume remaining word characters: caus*, mechanis*, therap*, clinic*, efficac*, effective*, treat*, cure*, prevent*, recommend*, prescri*, bind*, affinit*, inhibit*, activat*, regulat*, driv* including drive and drives, and induc*. It additionally refuses pathogen*, diagnos*, disease association separated by whitespace or hyphens, truth, and physical validity separated by whitespace or hyphens. The check is incomplete, is not a language-understanding guarantee, and refuses negations too. The same families are declared in quality.json and code.

Failure handling: claim-boundary runs before evidence-status gates; empty-evidence, self-evidence, unavailable-evidence, non-evidence-support, replication-unavailable and unavailable-positive remain distinct. No approval implies truth. Preserve null and failed controls, excluded samples/sites, original rules and negative outcomes. The coordinator chooses rigor and independent record, source and method review; any installation, restricted transfer, new host, heavy/GPU/remote compute or interpretation-changing choice requires its applicable approval, outside this offline pack.

## Frozen acceptance controls

`negative-cases.json` follows the existing synthetic fixture format with fixture and cases; it adds no domain record schema. Each case has id, finding, target, path, value and operation; it mutates only a temporary synthetic copy. Operations set, remove and changed-rules are exercised by individual tests. The benchmark in `benchmarks/workflow-callset-qc/tasks.json` freezes questions, acceptance criteria and CPU-only budgets. `tests/test_workflow_vcf_pack.py` checks hand arithmetic, all seeded refusals, guard sensitivity, strict records, resource edges, CLI refusals, read-only concurrency and descriptor replacement attacks. These controls validate software behavior only.
